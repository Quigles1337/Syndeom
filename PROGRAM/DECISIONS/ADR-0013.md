## Context

  manifests: 37 `s1_ingest`, one each of `s1_derive`, `s1_pair` and `s1_pair_archive`. Session 23
  projected 40 archived representations and 37 effective logical items; no tool has counted them.
- **The pinned inventory is code for one event.** `s1_effective_inventory` compiles the accepted
  baseline list (`BASE` `37f1d598…`), validates the one first-parent amendment and pins the

- **The pinned coverage tool is code for one prefix.** `s1_4_coverage` pins its corpus revision
  (PR 4's merge), its tool closure (`analysis/s1-4/tool-inputs.txt`) and its config, and counts the

  a later prefix under its own gate record; it never rewrites the Gate S1 table". D9 fixes the

- **What the pinned modules expose.** `effective.rs` makes `frozen`, `input_set` and
  `validate_case` public; `coverage.rs` makes `taxonomy`, `lineage`, `validate_labels`, `harvest`,
  `qualify`, `lengths`, `octave_edges`, `coverage`, `Item` and `Bins` public. The assembly steps
  (`effective::inventory`, `coverage::items`, `report`, `render`) are private and pinned, so a new
  revision re-does them around the public pieces.
- **Rulings that bind.** Al's rulings of 2026-10-28 on PR 23 (Q-H1..Q-H7) and on the event's scope
  (Session 38: "The inventory event (new tool revision + coverage run) becomes NEXT, in its own
  PR"). ADR-0011 D6 keeps every S1 item, the five included, out of any generator seed.
- Leakage (SD8): nothing here touches contact material, a detector, a threshold or a generator.

## Options considered

1. **Parameterize the pinned tools** — rejected: it changes pinned bytes (ADR-0012 D7; STATE's
   bounds), and the retained reports would no longer name the tool that wrote them.
2. **Two new tools and two packets** — an inventory revision in `engine/ingest/` and a coverage
   revision in `engine/manifest/` — rejected: both need the same effective grouping, preservation
   and population pin, so the logic would be written twice and could drift.
3. **One new tool revision in new files, one packet holding the inventory and the coverage run** —
   **chosen** (flag A, accepted).

## Decision

### D1 — The event and the tool

The event is `first-later-prefix-inventory-2026-10-28`. The example `s1_later_prefix` (crate
`syndeom-ingest`; support module `later_prefix.rs`) reads Git objects at `HEAD` of a clean
checkout, like the pinned inventory, and writes `inventory.json`, `coverage.json`, `report.md` and
`provenance.json` into a new directory outside the repository:

```
cargo run --locked -p syndeom-ingest --example s1_later_prefix -- <repo> <new-output-directory-outside-repo>
```

The packet `analysis/s1-later-prefix-1/` keeps the pins (`config/`), the retained outputs
(`report/`) and a README. The tool compiles its own sources, the two pinned modules, the manifest
crate, the Cargo files and the toolchain pin, and refuses if the checkout's copies differ.

### D2 — The prefix's pins

`config/prefix-inputs.json` records the freeze point `d2569d61588368a60bbf7558fb9f0703f96e3a5b`
(tree `1e2fafad…9bd7`), the five item directories with their ten files (manifest and record, each
with SHA-256 and length), and the harvest log as it stood there (56,562 bytes, `58af93f1…5c8c`).
The tool checks that these pins bind the freeze point's five directories exactly and its whole
log, that the freeze point is an ancestor of `HEAD`, and that `HEAD`'s copies of the two config
files and of the accepted baseline list equal the compiled copies.

### D3 — What is checked, and nothing else

- ADR-0012's input set (79 files) and the frozen S1.4 bins, against the accepted baseline.
- The ten prefix files, against their pins.
- The harvest log's pinned prefix, which must be an exact prefix of the current file. Only that
  prefix is parsed, so rows a later harvest appends neither change nor stop this event.
- Additions under `groundtruth/` are refused besides the amendment map, the effective
  representation's directory and the prefix's files.

Every other file is unchecked, as ADR-0012 D2 leaves it.

### D4 — The prefix's review overlay

`config/dispositions.json` (schema `s1-later-prefix-overlay/1`) lists each of the five prefix
roots once, with no issues and a basis: `analysis/s1-held-harvest-review/REVIEW.md` (five agree)
and Al's rulings recorded in STATE, which settled every reading the review raised as recorded
(Q-H1, Q-H2/Q-H3, Q-H5). Q-H4's further unnamed results enter as a scope note beside the existing
unnamed-result question. The overlay names the frozen S1.4 overlay and its digest. That overlay
still governs the accepted corpus's roots, with the first-parent hold discharged by the accepted
amendment, as in the pinned inventory. The tool refuses an overlay that misses a prefix root,
lists any other root, or carries an unknown issue kind or an empty basis (flag B, accepted: an
item is flagged by a recorded open issue, and a later issue enters through the overlay).

### D5 — The labels counted

The coverage counts the **effective** logical items, with the effective representation's labels:
the accepted first-parent amendment applied, so item `63e23a952084` carries the labels of
`15ab865466d6`. The frozen S1.4 table counted the historical roots before that amendment and stays
frozen history (flag C, accepted). The packet names which labels it used and the amendment map:
`coverage.json` carries `label_basis` and `amendment_map` (the path
`groundtruth/amendment-map.json`, its SHA-256, the logical item key and the effective artifact
id), `report.md` states both, and `inventory.json` carries the map's content as `mapping`.

### D6 — The coverage table (ADR-0003 D9)

For the prefix through arXiv id `1404.4599`:
- one row per FLAW-0001..0014 and a total row, built by the pinned `coverage()`, for the whole
  prefix and for the unflagged documented subset;
- the frozen bins, re-verified to be the octave grid of the population's canonical lengths. The
  five items are raw-only, so they add no length, and the grid is unchanged. A later event that
  adds lengths outside the grid decides what to do in its own ADR;
- the zero-coverage classes, the undetermined-truth items, the candidate counts and the interim
  power sentence;
- `report.md`, rendered by the tool from `coverage.json`.

The Gate S1 table and the frozen S1.4 packet are not rewritten. This packet is the later prefix's
own record.

### D7 — The population pin (as amended by Al's ruling of 2026-10-28 on PR 25)

The population is pinned by D2's recorded inputs and by nothing else: the accepted integration's
input set and the five prefix item directories, by name and byte hash, with the harvest log read
to its pinned prefix (D3). A file missing from those inputs, a changed byte in them, or an
addition under `groundtruth/` outside them is refused; every manifest the census reads is
therefore fixed by those inputs.

The counts are measured outputs, recorded in the packet and frozen there. They are not conditions
in the code: the tool compares no count with a literal, and its messages state none. The scope
("through candidate 30, `1404.4599`") is measured from the harvest log's pinned prefix and
reported as `prefix_through_candidate` and `prefix_through_arxiv_id`, with `scope_source` naming
where it came from. What the tool still checks are identities:
- every review names a logical item;
- the amended item aliases exactly its two representations;
- the harvest log's admissions equal the corpus roots, the prefix's roots among them.

A later prefix is its own event, with its own recorded inputs and tool revision, as this one is.
The pinned ADR-0012 tool keeps its literals: it is frozen, and this rule applies from this event
on.

### D8 — Tests (as amended by Al's ruling of 2026-10-28 on PR 25)

`engine/ingest/tests/later_prefix.rs`, under the gate. No test asserts a literal count.
- **Byte identity:** the working tree yields the retained `inventory.json`, `coverage.json` and
  `report.md`, byte-identical. This is where the measured counts are frozen.
- **The population follows the recorded inputs:**
  - the representations equal the manifests among the fixture's recorded inputs, and raw plus
    canonical equals that number;
  - the prefix's logical items are the prefix directories, each present as an item of this event;
  - the logical items equal the items listed;
  - the candidates, the last candidate's index and its arXiv id are those of the harvest log's
    pinned prefix;
  - the table has one row per taxonomy class plus a total row equal to the logical items;
  - `coverage.json` names the amendment map.
- a byte appended or flipped in a prefix manifest or record, the taxonomy, the bins, the S1.4
  overlay or an accepted item's manifest fails;
- a removed prefix file fails, and an addition under `groundtruth/` fails;
- a row appended to the harvest log is not read, and leaves both outputs equal to the unchanged
  fixture's, while a changed byte inside the pinned prefix fails;
- changes outside the inputs leave both outputs equal to the unchanged fixture's: STATE, SOURCES,
  the constitution, the workspace manifest, the README, an S2 crate and a receipt in the packet;
- the overlay must list exactly the prefix's roots, with known issue kinds and a basis;
- a prefix issue moves its item out of the unflagged subset.

The fixture reads a fixed list of files, so a later prefix's directories cannot enter it.

### D9 — What this ADR does not decide

- **The freeze-register row for this packet** (flag D). It is a register edit under a ruling;
  Al's ruling puts it in this pull request's final commit (*Amendments* 1).
- Canonical lengths and external-byte verification stay prerequisites for scoring real items (S4).
- The harvest stays paused after candidate 30, and candidate 31 (`1406.7174`) stays undecided.
