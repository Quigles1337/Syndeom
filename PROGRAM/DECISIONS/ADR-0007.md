## D1 — Eligibility and independent evidence

Select a short, independently published statement with resolvable definitions/hypotheses and
an exact declaration at the existing Mathlib pin. Retrieve the primary publication this
session; retain exact source bytes, author/title/edition, theorem/section/page, URL, UTC access
time, content digest, and actual reuse terms. Record those before ingestion. A locator is
edition-specific; search snippets and a title match do not settle it.

The claim must come from the publication. Executor transcription, translation, paraphrase,
pair selection and wrapper authorship are separately attributed. A Lean back-translation
is not an independently published source. Synthetic fixtures remain synthetic. A first
candidate that fails may be followed by at most two alternatives, with reasons recorded;
this procedure is not another harvest campaign.

Select Judson 2025 Theorem 2.2.6. Its published prime definition is in the same subsection
and on the same page. The official PDF contains an explicit GFDL-1.2-or-later grant with
no invariant sections or cover texts (its Appendix A reproduces version 1.3). Mathlib's
pinned source headers and LICENSE specify Apache-2.0. No inferred erratum or withdrawal is
involved. This selection is independent documentary provenance, not a claim that the author
and Mathlib developed Euclid's theorem independently.

## D2 — Claim of record, offered argument and semantic review

For a pair the informal claim is the claim of record. Review objects/domains, quantifier
order, explicit and implicit hypotheses, definitions/conventions, every coercion or
translation, and conclusion/scope against the actual source and elaborated Lean type.
Explain the correspondence itself; a proved equivalence between two true propositions
does not establish source fidelity.

This candidate uses the published statement alone. The source does contain a printed proof,
but that proof is not the selected offered argument. The offered argument is the existing
Mathlib theorem's proof, referenced by a new, distinctly named alias. `proof.md` has zero
informal proof steps; its mandatory `**Proof.**` and terminator lines are format delimiters,
not assertions that a missing informal derivation was supplied. Do not manufacture steps
from the Mathlib proof or label them as Judson's. The packet reviews the formal argument's
target and dependencies; it does not assert line-by-line fidelity to Judson's argument.

For this selection the positive-integer prime definition is carried to naturals via the
usual value-preserving bijection. Primes are greater than one, so zero and negative integers
are not lost cases. `Nat.prime_def` spells out the divisor convention; `Set.Infinite`
means the prime subtype is not finite. The packet's correspondence table addresses the
zero-divisor edge case and states that no theorem parameter or typeclass assumption is added.
Any unresolved mathematical mismatch prevents acceptance, regardless of compilation.

## D5 — Small deterministic producer to implement later

Add one narrow Rust crate, tentatively `syndeom-pair`, with archive and canonical modes:
`s1_pair_archive` 0.1.0 and `s1_pair` 0.1.0 respectively. These are proposed identities,
not existing binaries or a new S2 generator family. Keep S1.1 `syndeom-ingest`'s invalid-proof
erratum/retraction restrictions intact. Do not extend the gzip/TeX-specific S1.3 producer.

Reuse `syndeom-manifest` for all JCS/config and byte hashing, IDs, parsers/counts,
`Manifest::check` and `Manifest::check_derived`; Python may orchestrate only. The producer
must refuse missing/extra/unknown configuration fields, alternate methods, wrong pins,
missing bytes, changed source/target hashes, unsupported declaration/type/template,
path aliases/escapes, mismatched metadata or an unreviewed semantic change.

Archive mode reads both actual source objects, checks their exact expected digests/lengths,
and creates the raw pair record only after the written source/argument review is accepted.
Canonical mode resolves the raw manifest at the repository item-of-record path, checks both
raw source bytes, the parent ID/config hash/producer provenance and intended item, and
renders exactly the reviewed recipe. Record the actual parent-manifest hash in the new
run receipt; do not guess one now before its real producer-containing commit exists.

Before either mode writes, validate the complete planned output set. Refuse different
existing bytes under the same ID; use exclusive creation and a new receipt destination.
An identical replay may succeed without rewriting historical files. An explicit dry run
must disclose whether output-collision checks execute; for this new producer require full
preflight even on dry runs. A partial or failed write never counts as an accepted pair.

**Executable provenance:** commit the implementation before real generation. Record that
actual 40-hex producer-containing commit in `engine_commit`, and verify its source inputs
byte-for-byte against the checkout: new crate sources/Cargo manifest, manifest library
sources/Cargo manifest, workspace Cargo manifest and lock, Rust pin, and any generation
templates or executable dependencies. Recipe bytes/config hashes identify runtime inputs;
the pinned Lean/Lake/Mathlib closure identifies checking inputs. Reject a convenient SHA
that predates the producer, or a dirty implementation that the SHA does not describe.
No `engine_commit` is available in this session because no producer is implemented.

## D6 — Required checks and acceptance/refusal

For the prospective admission, perform all of the following with actual input/output bytes:

1. `parent.check(FileBytes { informal: Some(raw_pdf), formal: Some(raw_module) })`.
2. `child.check(FileBytes { informal: Some(proof_md), formal: Some(proof_lean) })`.
3. `child.check_derived(&parent)`, plus stricter producer checks: parent is a raw pair,
   child a canonical pair, identical sources/item/licence/status/toolchain and all ground
   truth; exact reviewed recipe, raw/target hashes and source mapping. The generic validator
   alone does not enforce every one of these producer obligations.
4. Compile the actual canonical Lean file with the pinned project; print its complete type
   and the target declaration's type with implicit arguments visible. No unaccounted
   parameters, instances, local definitions or namespace shadowing.
5. `#print axioms` on both declarations and the principal dependency chain. Require the
   transitive axiom set to be a subset of `propext`, `Classical.choice`, `Quot.sound`;
   reject `sorryAx`, added axioms, `Lean.ofReduceBool` or any other constant. Inspect the
   proof dependency bodies. Import success alone is insufficient.
6. Independent fresh-output replay from the committed producer; compare all output bytes,
   hashes/counts and serialized metadata. Focused refusal tests cover changed raw bytes,
   wrong declaration/type, status or parent mismatch, output conflicts and producer SHA.
   Run the complete repository gate on the final staged/committed tree.
7. Accept only when the publication's specified claim, formal declaration, actual offered
   argument and all provenance records agree. Keep missing support explicitly unresolved.

The current analysis rehearsal calls only pure format/count/hash/ID APIs and Lean inspection.
It does **not** construct a `Manifest`, execute full-manifest/parent-child validation, or
exercise an unimplemented producer. The packet reports this distinction and its actual
commands, including the two corrected development harness failures.
