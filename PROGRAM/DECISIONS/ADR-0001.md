## Context

SD1 names the mandatory manifest fields: generator ID + version, full config, seed, taxonomy
version, ground truth (`correct`, flaw classes, location, severity, Lean-catchable), content hash.
Five other rules shape the schema:

- **SD6** — every result records engine commit, seed, config hash, taxonomy version; a manifest is
  the carrier of those for its artifact, and the config hash must be computable identically on any
  platform. For LLM-assisted generators SD6 adds model id and version, prompt hash, sampling
  parameters, and output content hash.
- **SD12** — a real item's ground truth is `documented-by-source` or `formalized-in-mathlib`, never
  `by-construction`; nothing synthetic is ever labeled real. The schema must make the two
  unmistakable in every manifest, not in a side file.
- **SD3 / SD8** — contact artifacts are real AI-generated manuscripts. The instrument carries no
  verdict about them. A contact manifest therefore carries **no ground truth at all**.
- **S2.2** — commanded versus achieved statistics with a per-artifact fidelity verdict (FRIEDMAN F5
  lineage): a flawed artifact counts only when the injected flaw is confirmed present — for
  Lean-catchable flaws, the kernel or tooling rejects the formal variant exactly as predicted.
- **S3.3** — leave-one-generator-out needs generator identity on every synthetic artifact.
- **FLAWS.md 0.1.0** fixes the vocabularies the manifest must carry: `lean_catchable` ∈
  {`YES-KERNEL`, `YES-TOOLING`, `NO`, `N/A`}; severity ∈ {`cosmetic`, `repairable`, `gap`,
  `fatal`}; two-dimensional ground truth (`statement_status` separate from `proof_status`); and it
  delegates the informal location rule ("step index and character span under the segmentation the
  ADR decides") and the formal one (`<declaration>:<line>`) to this ADR.

**What FRIEDMAN decided (read at `7c3e5dd`).** D1 JSON in the I-JSON subset, on-disk pretty form with
JCS-ordered keys and one trailing LF; D2 `corpora/<corpus_id>/manifest.json` with `corpus_id =
<generator.id>-v<generator.version>-<config_hash[0:12]>-s<seed>`, a pure function tested as an
engine invariant; D3 a byte format for the corpus; D4 the field table, tolerance forms `abs`/`rel`/
`exact`, verdict on the point estimate, `ci95` outside the verdict, missing/null achieved → FAIL,
no wall-clock timestamps; D5 SHA-256 over RFC 8785 (JCS) bytes for `config_hash` and over exact
bytes for `content_hash`; D6 a golden over fixed bytes; D7 the handshake surface. ADR-0004 pins the
D4 arithmetic to IEEE 754 binary64, round-to-nearest-even, no fused operations, `<=` inclusive, with
seven conformance vectors. The crate `friedman-manifest` derives every struct with
`deny_unknown_fields` and its `check` rejects any `manifest_schema` other than
`"friedman-manifest/1"`, any `origin` other than `"synthetic"`, and any `ground_truth.label` other
than `"mechanism"`. A FRIEDMAN consumer therefore cannot parse a SYNDEOM manifest, and Al ruled
(Q10 (a)) that compatibility is **structural**: same semantics for every field that shares a name,
same hashing, same id discipline, same handshake pattern, a new schema string, and no FRIEDMAN-side
change ever required by SYNDEOM.

## Options considered

1. **Same schema string, added fields.** Rejected: the FRIEDMAN crate rejects unknown fields, and
   FRIEDMAN's `corpus` block (a token stream of documents) has no proof-artifact meaning; pretending
   the two are one schema would be a dependency in disguise (SD14).
2. **New schema string `syndeom-manifest/1`, structurally identical where names coincide.**
   Chosen (Q10 (a)). Shared names: `manifest_schema`, `origin`, `generator`, `engine_commit`,
   `seed`, `config`, `config_hash`, `ground_truth` (extended), `commanded`, `achieved`, `fidelity`,
   `notes`; FRIEDMAN's `corpus_id` becomes `artifact_id` with the same derivation and FRIEDMAN's
   `corpus` becomes `artifact` (a proof is not a token stream).
3. **One schema per origin.** Rejected: three shapes triple every consumer; one shape with
   origin-conditional fields (`seed`, `toolchain`, `ground_truth`) keeps the self-check in one place.

Two sub-choices the rulings left open:

- **Informal location unit.** Byte offsets are what `sha256sum`-style tooling sees; code points
  (Unicode scalar values) are what Q11's "character span" says, can never split a character, and are
  what Rust `str::chars()` and Python string indexing index directly. **Code points chosen**; D8
  shows a span where the two differ.
- **Real items that are not Markdown.** S1.1 errata arrive as PDFs or LaTeX, and contact corpora as
  whatever the corpus holds. Q11's "UTF-8 Markdown with generator-numbered steps" describes what the
  generator emits. Rather than forcing a conversion that would itself be an unlabeled
  transformation, a third byte format `raw/1` (bytes as received; locations by a free-text locator)
  is admitted for ingested files, and the manifest says which format each file has.

## Decision

### D1 — Format and on-disk form (inherited verbatim from FRIEDMAN D1)

Manifests are JSON restricted to the I-JSON subset RFC 8785 requires (no NaN/Infinity, no duplicate
keys, numbers are IEEE 754 doubles or integers within double range). One manifest per artifact,
file name `manifest.json`. On-disk form: UTF-8, no BOM, 2-space indent, object keys sorted per JCS
order at every level, single trailing LF — a presentation rule so regenerated manifests are
byte-identical and diffs are meaningful; it is **not** the hashing form (D5).

### D2 — Layout, `artifact_id`, and storage

```
<root>/<artifact_id>/manifest.json
<root>/<artifact_id>/proof.md       present iff artifact.kind ∈ {informal, pair} and the file is stored
<root>/<artifact_id>/Proof.lean     present iff artifact.kind ∈ {formal, pair} and the file is stored
```

`<root>` is fixed by `origin` (§3.8 layout): `synthetic` → `corpora/`, `ground-truth` →
`groundtruth/`, `contact` → `contact/`. A manifest found under the wrong root fails its self-check.
For `raw/1` files (D3) the file name keeps the source's extension (e.g. `proof.pdf`) and is
recorded in `artifact.files.<k>.file`.

`artifact_id` is a pure function of (producer, config, seed):

- synthetic: `<generator.id>-v<generator.version>-<config_hash[0:12]>-s<seed>` (FRIEDMAN D2 form);
- ground-truth and contact (`seed` is `null`): `<generator.id>-v<generator.version>-<config_hash[0:12]>`.

Two artifacts with the same id must be byte-identical in every stored file; that is an engine
invariant tested at S2.3, not a convention. A `pair` is one artifact: one id, one manifest, two
files (Q11).

Storage is recorded per file in `artifact.files.<k>.storage` ∈ {`"committed"` (bytes in the repo),
`"regenerable"` (synthetic; regenerate from the manifest, verify by `content_hash`), `"external"`
(licence forbids a stored copy — SD16; `config.sources` names the S-entry holding URL and access
record, and the hash still pins what was read)}. `manifest.json` is always committed. The default
for synthetic files (committed or regenerable) is an ADR-0002 decision once real sizes exist
(FRIEDMAN ADR-0002 D3 precedent); the enum is fixed here.

### D3 — Byte formats

**`syndeom-informal-md/1`** (what the generator emits; the S1.2 informal statements may also use it).
UTF-8, no BOM, no U+000D, no U+0009, no trailing U+0020 on any line, exactly one trailing U+000A.
The document is a sequence of *paragraphs* (maximal runs of non-blank lines) separated by exactly
one blank line, in this fixed order:

1. a title line `# <title>`;
2. the **statement paragraph**, beginning with the marker `**Theorem.** ` (marker includes one
   trailing U+0020) — this is **step 0**;
3. the line `**Proof.**` alone;
4. **steps 1..n**, one paragraph each, beginning with the marker `**Step k.** ` where k are
   consecutive integers from 1 in document order, numbered by the generator;
5. the terminator line consisting of U+220E (`∎`) alone, which is the last line of the file.

A paragraph may wrap over several lines; its internal line breaks are U+000A and are part of its
text. **Step text** is the paragraph's text after its marker, up to but excluding the paragraph's
final U+000A. Markdown and LaTeX math (`$…$`, `$$…$$`) are permitted inside paragraphs.

- **Location of an informal instance:** `{"artifact": "informal", "step": k, "span": [s, e]}` with
  `0 ≤ s ≤ e ≤ len(step text)` in **Unicode scalar values** (code points), half-open `[s, e)`.
  Spans index the Unicode scalar values obtained by decoding the stored bytes as UTF-8, with no
  normalization and no grapheme clustering (Al, Session 4). `s == e` denotes an *omission point*
  (FLAW-0005 gap, FLAW-0006 dropped base case, FLAW-0014 deleted branch): the place where the
  missing material would attach. Step 0 addresses the statement (FLAW-0008, FLAW-0012).
- **Counts:** `n_steps` = n (step 0 excluded); `n_lemmas` = number of steps k ≥ 1 whose text begins
  with `Lemma ` followed by a positive decimal integer and `.`; `n_tokens` = the sum over steps
  0..n of the number of maximal runs of non-whitespace code points in the step text (whitespace =
  U+0009, U+000A, U+000D, U+0020); `n_bytes` = file length. Markers, the title, and the terminator
  are counted in no statistic.

**`syndeom-lean/1`** (what the generator emits; S1.2 formal statements may also use it). One Lean 4
source file: UTF-8, no BOM, no U+000D, no U+0009, no trailing U+0020 on any line, exactly one
trailing U+000A. Its `import` lines name only `Mathlib` or `Mathlib.*` modules. Exactly one
declaration is the claim of record, named in `artifact.files.formal.main_declaration`.

- **Location of a formal instance:** `{"artifact": "formal", "declaration": "<name>", "line": l}`
  — `l` is the 1-based line number in the file and `<name>` the top-level declaration whose source
  range contains line `l` (for FLAW-0009 the `axiom` itself; for FLAW-0008 the main declaration at
  its statement line).
- **Counts:** `n_lines` = number of U+000A; `n_declarations` = number of lines beginning at column 0
  with one of `theorem`, `lemma`, `def`, `axiom`, `instance`, `abbrev`, `structure`, `inductive`,
  `opaque`, `example`; `n_tokens` = maximal runs of non-whitespace code points over the whole file;
  `n_bytes` = file length. Whether the file builds is **not** a format property; it is the
  `lean_build` achieved statistic (D4).

**`raw/1`** (ingested files only; never emitted by a generator; an **archival** format, Al,
Session 4). Bytes exactly as received, any type. Only `n_bytes` and `content_hash` are defined;
every other count is `null`. Location of an instance: `{"artifact": "informal" | "formal",
"locator": "<text>"}` — the locator is transcribed from the documenting source (page, theorem
number, equation; S1.1 "the flaw's location"). A `raw/1` file therefore has **no position on the
proof-length axis, no step locations, and nothing a detector can consume**; detectors consume only
`syndeom-informal-md/1` and `syndeom-lean/1`. How a real item nonetheless gets scored is the
derived-canonical-artifact convention in D4.

### D4 — Schema `syndeom-manifest/1`

Top-level object; every field required unless marked optional; `null` only where stated.

| Field | Type | Meaning |
|---|---|---|
| `manifest_schema` | string | exactly `"syndeom-manifest/1"` |
| `artifact_id` | string | per D2 |
| `origin` | string | `"synthetic"` / `"ground-truth"` / `"contact"` (Q11) |
| `generator` | object | the versioned, deterministic **producer** of the artifact directory: `id` (snake_case), `version` (semver), `rng` (names the RNG and how sub-streams derive from `seed`; **any change bumps `version`**; `"none"` for an ingest procedure, which has no randomness). For synthetic artifacts this is FRIEDMAN's field exactly; for the two real origins it names the ingest script in `engine/` that wrote the directory. Optional `llm` sub-object per D7 |
| `engine_commit` | string | 40-hex lowercase git SHA of this repository that produced the directory (SD6) |
| `seed` | integer or null | master seed in unsigned 64-bit range for synthetic artifacts; `null` iff `origin ≠ "synthetic"` |
| `config` | object | the producer's **full** configuration, no defaults elided. For ingest producers it must contain `sources` (array of `S-NNNN` ids), `item` (string identifying the item within the source), `licence` (string, SPDX id or the licence's own words — SD16, recorded before ingestion), and `status` `{ "kind": "erratum" / "retraction" / "mathlib" / "none", "reference": string }` naming the document or declaration that establishes the item's status (SD12) |
| `config_hash` | string | SHA-256 hex (lowercase) of JCS(`config`) — D5 |
| `toolchain` | object or null | `{ "lean": string, "mathlib": string }` — the exact `lean-toolchain` line and the 40-hex Mathlib commit the formal file was built against, **read** from `lean/lean-toolchain` and `lean/lake-manifest.json` (after ADR-0002) or, for a contact corpus, from the corpus's own pin files (S-0001 records the first such pair); `null` iff no formal file is present |
| `artifact` | object | `kind` ∈ {`"informal"`, `"formal"`, `"pair"`}; `files` object with key `informal` iff kind ∈ {informal, pair} and key `formal` iff kind ∈ {formal, pair}; each a **file record** (below) |
| `ground_truth` | object or null | **`null` iff `origin == "contact"`** (SD3: the instrument carries no verdict about a real AI manuscript; post-hoc annotations, if any, live in S5 analysis files, never here). Otherwise: `derivation` ∈ {`"by-construction"` (synthetic only), `"documented-by-source"`, `"formalized-in-mathlib"`} (SD12); `statement_status` `{ "value": true / false, "method": "mathlib" / "lean-kernel" / "source-document" / "counterexample", "reference": string }` — how the statement's truth value was established (a Mathlib declaration name at the pinned commit; a sorry-free declaration in this repo's `lean/` with standard axioms; an S-entry; or the counterexample itself, written so it can be checked); `proof_status` ∈ {`"valid"`, `"invalid"`} — the status of the offered proof **as an argument for the claim of record** (the informal statement for `informal` and `pair`; the Lean statement for `formal`), so a Lean proof of a drifted statement (FLAW-0008) makes a pair `invalid` even though the file builds; `correct` (boolean, **derived**: `statement_status.value && proof_status == "valid"` — the SD1 bit; a correct artifact may still list cosmetic flaws, e.g. FLAW-0013 padding, SD5); `flaws` (array of flaw records, below; may be empty); `taxonomy_version` (string, the `PROGRAM/FLAWS.md` version these records are read against; `"0.1.0"` now) |
| `commanded` | object | map statistic-key → `{ "value": V, "tolerance": T }` — what the producer was told to hit (FRIEDMAN D4 shape); **empty `{}` for the two real origins** (nothing is commanded of a real item) |
| `achieved` | object | map statistic-key → `{ "value": V or null, "estimator": string, "ci95": [lo, hi] or null, "reason": string (required iff value is null) }` — what the engine measured on the stored bytes; may contain keys not in `commanded` |
| `fidelity` | object | `per_statistic` (map over every key in `commanded` → `"PASS"` / `"FAIL"`), `verdict` (`"PASS"` iff every per-statistic verdict is PASS) — vacuously PASS for the real origins; the S2.2 verdict for synthetic ones |
| `notes` | string, optional | free text; never load-bearing |

**File record** (`artifact.files.informal` / `artifact.files.formal`): `file` (name per D2),
`format` (`"syndeom-informal-md/1"` or `"raw/1"` for informal; `"syndeom-lean/1"` or `"raw/1"` for
formal), `storage` (D2 enum), `content_hash` (SHA-256 over the exact bytes), `n_bytes` (integer),
and the format's counts — informal: `n_tokens`, `n_steps`, `n_lemmas`; formal: `n_tokens`,
`n_lines`, `n_declarations`, `main_declaration` (string) — each `null` iff `format == "raw/1"`.

**Flaw record** (`ground_truth.flaws[]`): `instance` (integer ≥ 1; the same instance injected into
both files of a pair yields two records sharing one `instance`), `class` (`FLAW-NNNN`, an entry of
FLAWS.md at `taxonomy_version`), `sub_variant` (string naming a sub-variant spelled in that entry,
e.g. FLAW-0001 `propagated` / `local`, FLAW-0003 `direct` / `cycle`; `null` when the entry names
none), `location` (one of the three D3 forms; its `artifact` key must match a present file),
`severity` (the instance's actual severity, within the entry's range), `lean_catchable` (the
instance's actual value from the entry's vocabulary — a FLAW-0003 `cycle` is `NO`, a `direct` is
`YES-KERNEL`), `dials` (object: the injector's dials for this instance, full, no defaults elided —
duplicating the relevant part of `config` on purpose so a record is self-describing).

**Consistency rules** (part of the schema; the self-check enforces them): `proof_status ==
"valid"` ⇒ every flaw's `severity` is `cosmetic`; `statement_status.value == false` ⇒ `proof_status
== "invalid"`; `derivation == "by-construction"` ⇔ `origin == "synthetic"`; `seed == null` ⇔
`origin ≠ "synthetic"`; `toolchain == null` ⇔ no formal file; `ground_truth == null` ⇔ `origin ==
"contact"`; `commanded == {}` for the real origins; the `<root>` matches `origin`.

**Derived canonical artifacts** (convention; Al's amendment, Session 4). Detectors consume only
`syndeom-informal-md/1` and `syndeom-lean/1`. Every S1 or S5 item that will be scored or placed on
the proof-length axis therefore gets a **derived artifact** in a canonical format, produced by a
versioned deterministic producer (`generator.rng` = `"none"`, `seed` = `null`) whose `config`
carries `derived_from` (the parent's `artifact_id`) and `method` (how the canonical form was
obtained — transcription, LaTeX conversion, autoformalization, …, with its tool and version). The
derived artifact's `origin` and `derivation` are the parent's; its `ground_truth` is the parent's
with each `location` re-expressed in D3 form (`step`/`span` or `declaration`/`line`), and the
re-expression is argued in writing in the S1.3 record (SD12) — a re-expression without that
argument is an unlabeled transformation and the derived artifact does not exist to this program
(SD1). For a contact parent the derived artifact's `ground_truth` is `null` like the parent's
(SD3). The parent `raw/1` artifact remains the **item of record**; the derived artifact is what the
battery sees. Self-check rules: `config.derived_from` names a manifest under the same `<root>`;
`origin`, `derivation`, `statement_status`, `proof_status`, `correct`, and the multiset of
`flaws[].class`/`sub_variant`/`severity`/`lean_catchable` equal the parent's; every derived
`location` is in D3 canonical form. The ingest and derivation procedures themselves are the S1.3
and S5.1 ADRs.

**Statistic keys** are snake_case identifiers from a registry that lives as code in `engine/` from
S2 on. The vocabulary this ADR names (shape fixed; list extensible by the S2 and S3 ADRs):
`n_tokens`, `n_steps`, `n_lemmas`, `padding_ratio` (tokens inside FLAW-0013 spans ÷ `n_tokens`),
`n_flaws_total`, `n_flaws_<NNNN>` (one per class, e.g. `n_flaws_0001`), `flaws_confirmed` (count
of injected instances confirmed present by the recorded S2.2 check), `lean_build` (`"pass"` /
`"fail"`: commanded = the kernel prediction from the flaw records, achieved = the build outcome at
`toolchain`), `lean_axioms_standard` (boolean: `#print axioms` of the main declaration shows at
most `propext`, `Classical.choice`, `Quot.sound`). The registry declares each key's JSON type
(integer vs number vs string vs boolean) because `exact` compares JSON values **structurally**: an
integer `0` and a number `0.0` are not equal under `exact` — use `abs` for ratios.

Deliberately absent, as in FRIEDMAN: **wall-clock timestamps** (byte-identical regeneration) and a
**battery version** (that belongs to results and reports, not to artifacts; SD6).

### D5 — Hashing (inherited from FRIEDMAN D5)

Every hash in a manifest is SHA-256, lowercase hex. `config_hash` = SHA-256 over the **JCS canonical
form** of `config` (RFC 8785, S-0007: no inter-token whitespace, §3.2.1; properties sorted
recursively by UTF-16 code units with arrays kept in order, §3.2.3; numbers serialized per ECMAScript
`Number::toString`, shortest round-trip, NaN/Infinity are errors, §3.2.2.3; UTF-8 output, §3.2.4).
`content_hash` = SHA-256 over a file's exact bytes. `prompt_hash` (D7) = SHA-256 over JCS of the
full prompt object. The engine needs a JCS-conformant serializer; FRIEDMAN's ADR-0002 D4 chose
`serde_json_canonicalizer 0.3.2` and tests it against the RFC's own vectors (§3.2 sample, Appendix
B). SYNDEOM's crate choice is made at S0.6 after re-reading crates.io (SD7) and must pass the same
vectors; nothing in this ADR depends on which crate.

### D6 — Tolerance arithmetic (FRIEDMAN ADR-0004 D1, adopted by reference)

Operands are parsed from JSON to IEEE 754 binary64 by correct rounding; the verdict is computed
entirely in binary64, round-to-nearest-even, no fused operations: `abs` PASS iff `fabs(a − c) <=
t`; `rel` PASS iff `fabs(a − c) <= r × fabs(c)` with the product rounded before the comparison;
`exact` PASS iff the JSON values are structurally equal. `<=` is inclusive. No decimal, rational, or
extended-precision path is permitted. `ci95` never enters the verdict. A commanded key missing from
`achieved`, or achieved `null`, is FAIL. FRIEDMAN ADR-0004's seven conformance vectors are SYNDEOM
conformance vectors: the engine crate carries them verbatim, and any consumer of SYNDEOM manifests
must pass them before consuming one.

### D7 — The SD6 clause for LLM-assisted producers

A producer that uses a language model is a separate generator family (Al's standing ruling, §2
S2.1) and carries `generator.llm`: `model_id` (string), `model_version` (string, the provider's
exact version identifier), `prompt_hash` (D5, over the full prompt object including system text and
every example), `sampling` (object: every sampling parameter the call set, full, including any
provider seed), `output_content_hash` (SHA-256 over the exact bytes the model returned before any
post-processing), `adr` (the id of the ADR that admitted this family under SD6; a family without one
is excluded from `battery-freeze-v1` by the freeze tooling). `generator.rng` is `"llm"` and the
top-level `seed` remains the engine's master seed for everything deterministic around the call. **An
artifact is counted only if its `output_content_hash` re-verifies against the stored bytes of the
file the model produced**; otherwise the self-check fails and the artifact is a finding, not a
corpus member (SD6: "an artifact whose bytes cannot be re-verified by hash is not a counted
artifact").

### D8 — Goldens (hand-computed over fixed bytes; a future engine test must reproduce them)

Both fixtures were written byte-for-byte by a script in Session 3 and every number below was then
computed from the bytes: digests with `sha256sum`, JCS forms by hand from the §3.2 rules and
cross-checked with Python `json.dumps(obj, sort_keys=True, separators=(",", ":"),
ensure_ascii=False)` — which coincides with JCS for these inputs only (ASCII keys, integers and
short decimals; the general case does not coincide, hence D5's real serializer). The same pipeline
reproduced FRIEDMAN's D6 vector (`22cdc154…dc33`, `8d106b97…75fd`) before being trusted here. Nothing
in D8 is a measurement of anything real.

**Golden A — informal artifact, `proof.md`, 279 bytes, 12 lines.** Exact text (every line ends with
U+000A; the file ends after the `∎` line's U+000A; the only non-ASCII code points are U+2014 `—`
(`e2 80 94`) on the Step 1 line and U+220E `∎` (`e2 88 8e`) on the last line):

```markdown
# Golden A

**Theorem.** For every natural number $n$, $n \le n^2$.

**Proof.**

**Step 1.** If $n = 0$, both sides equal $0$ — there is nothing to prove.

**Step 2.** Otherwise $n \ge 1$; multiplying both sides by $n \ge 0$ gives $n \cdot n \ge n$,
that is, $n^2 \ge n$.

∎
```

- `content_hash` = `0ac164476b6cedcd3c68194d8e65d3a602c0a7aa97e9e30f133602600712a6a1`
- segmentation: step 0 text = `For every natural number $n$, $n \le n^2$.` (42 code points, 8
  tokens); step 1 text = 61 code points / 63 bytes, 14 tokens; step 2 text = 103 code points,
  22 tokens, containing one U+000A after `$n \cdot n \ge n$,`. **`n_steps` = 2, `n_lemmas` = 0,
  `n_tokens` = 44.**
- span example (D3): the substring `there is nothing to prove` of step 1 is
  `{"artifact": "informal", "step": 1, "span": [35, 60]}` in code points; in bytes it would be
  `[37, 62)` because of the em dash before it — which is why the unit is fixed by this ADR.

### D9 — The sibling handshake surface (FRIEDMAN D7 pattern)

What a sibling or any outside consumer may consume, and all it may consume: a directory
`<root>/<artifact_id>/` holding `manifest.json` (schema `syndeom-manifest/1`) and whatever files the
manifest says are stored. The fields a decoy or calibration consumer needs: `origin` (a consumer
**must refuse `"contact"` artifacts** as decoys or labeled items — they are unlabeled real
manuscripts, SD8), `artifact.kind`, `artifact.files.<k>.content_hash` (pin what was copied),
`ground_truth.correct`, `ground_truth.derivation` (never treat `by-construction` as real, SD12),
`ground_truth.flaws[].class`, `ground_truth.taxonomy_version`, and `fidelity.verdict` (refuse FAIL).
Consumers copy by content hash into their own provenance-tracked sources under their own rules;
they never import SYNDEOM code, and SYNDEOM imports neither sibling's code (SD14). FRIEDMAN's crate
as read at `7c3e5dd` cannot parse this schema and is not expected to: SYNDEOM never requires a
FRIEDMAN-side change (Q10). Schema evolution is a new version string; consumers pin the string they
understand.

## Rationale (the choices the rulings left open)

- **`generator` as "producer" for real items** keeps one struct and one id function for all three
  origins, and makes an ingest reproducible the way a generation is (script + config → directory),
  while the content itself is pinned by hash rather than regenerated. The alternative — a separate
  `ingest` object — would have made every consumer branch on origin for no gain.
- **`ground_truth: null` for contact** encodes SD3 in the schema instead of in discipline: no field
  exists in which a verdict about a real manuscript could be written.
- **`correct` derived, not authored** removes one way to mislabel (SD1): the bit cannot disagree
  with the two statuses it summarizes.
- **`proof_status` judged against the claim of record** is what makes FLAW-0008 a flaw rather than
  a feature: the building Lean file is `invalid` as a proof of the informal statement, which is
  exactly SD2(iii).
- **Code-point spans** honor "character span" literally and cannot split a character; the D8 example
  shows the unit matters.
- **`raw/1`** admits real items without an unlabeled conversion; their locations are the documenting
  source's own words.
