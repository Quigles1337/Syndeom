- **The input set, read from the tool (SD7).** `inventory()` reads `PROGRAM/FLAWS.md` (the
  taxonomy), every `groundtruth/*/manifest.json`, each item's `RECORD.md` (presence), the artifact
  files a manifest names when their storage is committed (`Manifest::check`), and
  `analysis/s1-4/config/dispositions.json`. `validate_case()` and `mapping()` read

- Leakage (SD8): nothing here touches contact material, a detector or a design decision.

## Options considered

1. **A fifth exception** for `engine/Cargo.toml` and `engine/Cargo.lock` — rejected: Al's
   direction of 2026-10-26 names the full narrowing as the next revision; every exception so far
   has been followed by the need for another.
2. **A hand-written list of the files the tool reads** — the right boundary, the wrong form: a
   list in the source can drift from the packet it is meant to describe.
3. **The boundary derived from the baseline list** — **chosen**: the input set is computed from
   `preservation-inputs.json` (an item directory is a baseline directory under `groundtruth/`
   that holds a `manifest.json`) plus the four named packet files, and the tool prints the list it
   checked.
4. **Narrow, but keep the frozen packets whole and the append-only prefixes** — rejected: those
   files are not inputs, so a receipt added to a packet or a byte changed in a HANDOFF entry
   would still stop a reproduction that does not depend on it. The packets' immutability is the
   program's commitment (STATE's bounds, review of every pull request, each packet's own
   receipts), not a property this data reproduction can certify.
5. **Keep the pair-input comparison for the pair crate's own sources only** — rejected: half a
   claim about a replay already pinned elsewhere, and any later change to the manifest crate
   would fail it again.

## Decision

### D1 — The input set

The reproduction's input set is every baseline file it reads: `PROGRAM/FLAWS.md`; every file of
every accepted item directory under `groundtruth/` (a baseline directory holding a
`manifest.json`); `analysis/s1-4/config/dispositions.json`; and the accepted-candidate packet
files `validate_case` compares — `analysis/s1-first-parent-status/WITNESS.md`,
`candidate-config.json`, and the candidate directory's `manifest.json` and
`original-0706.0357v70.tar.gz`. At the accepted baseline that is **79 of the 375 files** (73 under
`groundtruth/`, 4 in the candidate packet, the taxonomy, the overlay). `input_set()` derives the
list from the compiled baseline; `preserve()` prints it as `preservation.inputs_checked`.

### D2 — What is checked, and nothing else

`preserve()` compares every input's length and SHA-256 with its baseline pin ("historical bytes
changed" on any difference, "missing input" if absent), and refuses any file under `groundtruth/`
that is not a baseline file, other than `groundtruth/amendment-map.json` and the effective
representation's directory, because the census enumerates that directory. No other baseline
file is read or compared: the constitution, every ADR, `SIBLING-MAP`, `scripts/check.sh`,
`lean/Audit.lean`, `engine/Cargo.toml`, `engine/Cargo.lock`, `LICENSE`, `README.md`,
`PROGRAM/STATE.md`, `PROGRAM/SOURCES.md`, `PROGRAM/HANDOFF.md` and `ADR-0003.md` beyond their
acceptance markers (which `validate_case` still requires), `groundtruth/README.md`,
`groundtruth/HARVEST-LOG.md`, `groundtruth/derivations/`, the other 43 files of the accepted
candidate packet, the other 34 files of the frozen S1.4 packet, and every engine source. Additions
outside `groundtruth/` are not refused.

### D3 — The four exceptions are replaced by the rule

The skip list (ADR-0009 D5; ADR-0010 D6 item 1), the append-only list (ADR-0010 D6 item 2) and the
licence-line restoration (ADR-0010 D6 item 3) are removed with the code that implemented them
(`LICENSE_LINE_FILES`, `license_line_restored`, `pair_input_unchanged`). None of those files is an
input, so none needs an exception.

### D4 — The pair-input comparison with the checkout is removed

`cli()` no longer compares the 20 pair inputs at `HEAD` with the producer revision. It still reads
`engine/pair/input-files.txt` and each listed file **from the producer revision's objects**, and
records their SHA-256 as `pair_input_hashes` beside `pair_producer_revision` — the same twenty
values as the retained provenance — and states the change in a new `pair_input_check` field. The
pair's replay claim stands exactly as STATE records it: the revision range, run at `c9372b1`.

### D5 — `engine/Cargo.toml` and `engine/Cargo.lock`

They remain in `COMPILED`: the tool is compiled from them, binds the examined tree's and the
working tree's bytes to the compiled copies, and records their digests in `tool_source_sha256`.
They are no longer pinned to the baseline (D2) and no longer compared with the producer revision
(D4). S2's first code commit may edit both; what the pair was built with stays recorded in
`pair_input_hashes`.

### D6 — The output

`inventory.json` changes only in its `preservation` object. Removed: `append_only_prefixes_checked`,
`s1_4_files_checked`, and `license_line_only_files_checked` (present only since ADR-0010, never in
the retained report). Added: `input_set_rule`, `baseline_files` (375),
`baseline_files_outside_input_set` (296), `groundtruth_item_files_checked` (73), `inputs_checked`
(the 79 paths). Changed: `exact_files_checked` 370 → 79 (369 at `HEAD` since ADR-0009),
`accepted_packet_files_checked` 47 → 4, and the two wording fields
`all_historical_groundtruth_objects` and `pair_producer_and_dependency_pins`. Every other byte of
the report — the event, the mapping, the counts, the 32 items, the actual byte checks, the scope
notes — is as retained. `provenance.json` gains `pair_input_check`; its `tool_source_sha256`
entries name this revision's sources; `checkout_revision` and `checkout_tree` name the checkout,
as always.

### D7 — What this ADR does not decide

- The population pin stays: the tool still refuses any count but 35 archived representations and
  32 effective logical items. Integrating the held harvest branch, or any later prefix, is its own
  inventory event with its own snapshot and tool revision, as STATE already says; D2's refusal of
  additions under `groundtruth/` is the same statement.
- The frozen packets, the registers and the append-only files are no longer byte-checked by this
  tool. Their immutability is the program's commitment, kept by STATE's bounds and by review.
- The S1.4 coverage tool (`engine/manifest/examples/s1_4_coverage.rs`) and its frozen packet are
  not touched: it pins its own corpus revision and tool closure.

### D8 — Tests

- `engine/ingest/tests/relicense_exceptions.rs` (6 tests asserting the three ADR-0010 exceptions)
  is replaced by `engine/ingest/tests/input_set.rs` (6 tests): the working tree passes and the
  report lists exactly the 79 inputs, every named inside file among them and 31 named outside
  files not; item directories come from the baseline (34, not `derivations/`) and the three
  non-baseline reads are bound elsewhere; a byte appended, flipped or removed in, or the removal
  of, each kind of input fails; a change, a rewrite or the removal of each of the 31 outside files
  passes — the constitution, ADR-0005, `SIBLING-MAP`, `scripts/check.sh`, `lean/Audit.lean`, the
  workspace manifest and lock file, the four crate manifests, the manifest and pair crate
  sources, the toolchain pins, `LICENSE`, `README`, STATE, SOURCES, HANDOFF, ADR-0003, CLAIMS, the
  corpus directory's three non-item files, S1.4 report and bins, two other candidate-packet
  files, the pair's proposed Lean input; the former exceptions together (any `LICENSE`, an appended
  SOURCES, a changed constitution, four `MIT` licence lines, an edited workspace manifest and lock
  file) pass; additions under `groundtruth/` fail and additions elsewhere pass (the amendment map,
  the effective representation's directory, a packet receipt, the owner decision, `ADR-0012.md`, an
  S2 crate, a manifest-crate module, a pair-crate module, a Lean seed module).
- `engine/ingest/tests/first_parent_amendment.rs` keeps 15 tests; two are rewritten to the new
  boundary: `accepted_inputs_in_every_scope_are_immutable` (a byte added to the amended item's
  manifest or record, the witness, the candidate config and manifest, the overlay or the taxonomy
  fails; a record added under `groundtruth/` fails) replaces the test that pinned the S1.4 packet
  and the pair crate, and `history_outside_the_acceptance_markers_is_not_pinned` (a flipped first
  byte of HANDOFF and of ADR-0003 passes `preserve()` and `validate_case()`) replaces the
  exact-prefix test. The other thirteen are unchanged.
- The gate's Rust test count stays 88 (ingest: 15 + 5 + 6).
