## Options considered

1. **Family structure.** (a) One monolithic generator with a flat config. (b) **Two producers
   behind one interface** — `s2_template`, hand-authored seed theorems with fixed, aligned informal
   and formal proofs, able to realize every FLAWS.md recipe the entry allows; and `s2_grammar`,
   generated derivation chains with a commanded length, realizing the mechanical subset of
   recipes — **chosen**: the FLAWS.md examples must become goldens (S2.4), which needs fixed
   bytes, while the proof-length axis needs generation; the two are different machines with one
   plan format (D2). (c) Grammar only — rejected: the FLAWS.md examples are not grammar outputs.
   (d) Templates only — rejected: no length axis.
2. **Randomness.** (a) `rand` + `rand_chacha` — two new pins, their licences (SD16, S-0008) and a
   stream whose stability is a property of a third-party crate's major version. (b) **A small
   generator specified in this ADR and implemented in the crate** (SplitMix64 seeding, xoshiro256**
   streams, labelled sub-streams; D4) — **chosen**: no new dependency, the stream is pinned by the
   engine commit, and `generator.rng` names a definition that lives in this repository. (c) A
   seed-indexed lookup table — rejected: it does not scale and hides the dials.
3. **Checking formal variants that are meant to fail.** (a) Library modules — impossible: the gate
   would be RED by design. (b) **Per-artifact `lake env lean` from `lean/` with the expected outcome
   asserted** (the S1.2 pattern) — **chosen**. (c) A scratch Lake package per artifact — rejected:
   manifest churn and cost for no gain.
4. **FLAW-0004's formal analogue.** (a) `sorry` — compiles with a warning and adds `sorryAx`, which
   makes it tooling-detectable, contradicting the entry's `YES-KERNEL`. (b) **The aligned tactic
   step omitted**, leaving an unsolved goal, which is an error — **chosen**.
5. **FLAW-0010 sub-variants (b) and (c)** (a real reference to the wrong work; the real work with
   an altered statement) need *real* references, which enter this program only as VERIFIED
   S-entries (SD11). **Deferred** to a later producer version with a reviewed reference lexicon
   drawn from SOURCES.md; v0.1 realizes sub-variant (a) only, fictional by construction.
6. **Where FAIL artifacts live.** ADR-0001 D2 fixes the root by `origin`, so a synthetic FAIL
   artifact stays under `corpora/` with `fidelity.verdict: "FAIL"`; D9 consumers refuse FAIL.
   A separate findings directory — rejected: it would fail the root rule.
7. **`cargo audit` in the gate** — rejected (offline gate). It runs at S2.4 and before the freeze,
   with its advisory-database commit recorded (D10).
8. **Padding as text inside steps versus whole steps.** Whole steps and whole lemmas — **chosen**:
   every FLAW-0013 span is then a whole step `[0, len)`, the padding ratio is a ratio of whole-step
   token counts, and the unpadded argument is recoverable by deleting the recorded steps.

## Decision

### D1 — Identity: one family, two producers, no new dependency

- The family is **deterministic seeded templates and grammars** (the standing ruling). It lives in
  one crate, `engine/generate/` → `syndeom-generate` 0.1.0 (binary `syndeom-generate`), edition
  2024, `#![forbid(unsafe_code)]`, `publish = false`, `license = "PolyForm-Noncommercial-1.0.0"`
  (ADR-0010 D1), dependencies `serde`, `serde_json` at the pins the other crates use and
  `syndeom-manifest` by path — **no new external dependency**, so S-0008 and `Cargo.lock`'s
  external entries are unchanged (`Cargo.lock` gains only the workspace member).
- Two producers, each a `generator.id` with its own semver `version`:
  - **`s2_template` 0.1.0** — hand-authored seed theorems (D6) with aligned informal and formal
    proofs; realizes every recipe its seed material supports.
  - **`s2_grammar` 0.1.0** — derivation grammars (D6) producing arguments of commanded length;
    realizes the recipes that need no hand-authored mathematics.
  Both carry `generator.rng = "syndeom-rng/1"` (D4) and `generator.llm` absent. Any change to the
  bytes a producer emits for some (config, seed), or to the labels it draws from the RNG, bumps
  that producer's `version` (ADR-0001 D4). Leave-one-generator-out (S3.3) treats the two as two
  generators.
- The ids are phase-prefixed like `s1_ingest`, `s1_derive` and `s1_pair`. ADR-0001 D8's
  illustrative ids `template-v0.1.0-…` remain what D8 says they are — byte fixtures for hashing
  and counting — and are not outputs of this family; D10 says how Golden A's and Golden B's bytes
  are nonetheless reproduced as a writer test.

### D2 — The shared interface: the plan

The interface behind which the four S2.1 modules sit is a **data structure, not a trait over
text**: the *plan*. Every module reads or rewrites the plan; only the renderers produce bytes.

```text
Plan
  theorem    : TheoremRef              -- a seed theorem id (s2_template) or a grammar instance (s2_grammar)
  statement  : { informal : String, formal : LeanStatement, imports : [String] }
  truth      : StatementTruth          -- true | false, with its witness (D7)
  steps      : [Step]                  -- the argument, k = 1..n in document order
  lemmas     : [Lemma]                 -- each rendered as a step whose text begins "Lemma N."
  padding    : [Padding]               -- FLAW-0013 insertions, each a whole step or lemma (D5)
  records    : [FlawRecord]            -- ground truth by construction, appended by the injector
Step
  index      : k
  informal   : String                  -- the step text (ADR-0001 D3), without its marker
  formal     : Option<Fragment>        -- the aligned Lean fragment: a `have` line or a tactic block
  premises   : [Premise]               -- earlier steps, lemmas, named theorems, citations
  site       : SiteKind                -- what recipes may act here, from the seed or grammar
```

- **Alignment** is the load-bearing property: a step has one informal rendering and one formal
  fragment, so a flaw injected at step k lands at a known span in `proof.md` and a known line in
  `Proof.lean`, and the two records of a pair share one `instance`.
- **Pipeline**, in a fixed order: `plan` (producer-specific) → `inject` (the recipes of D5, each
  appending its record and rewriting the plan) → `pad` (FLAW-0013) → `render` (the
  `syndeom-informal-md/1` writer and the `syndeom-lean/1` writer) → `measure` (achieved
  statistics from `syndeom-manifest`'s parsers and the Lean harness, D8) → `manifest` (D9) →
  `write`. The four S2.1 modules are: informal generator = `plan` + the informal renderer; formal
  variant generator = `plan` + the formal renderer; flaw injector = `inject`; padding module =
  `pad`. The two producers differ only in `plan`.
- **Rendering rules.** The informal renderer emits exactly ADR-0001 D3: title, `**Theorem.** ` +
  statement, `**Proof.**`, `**Step k.** ` paragraphs, the `∎` terminator, one trailing LF, no CR,
  no tab, no trailing space; a lemma is a step whose text begins `Lemma N.` with N numbered in
  order; the renderer re-numbers steps after injection and padding so k is always consecutive.
  The formal renderer emits exactly `syndeom-lean/1`: `import` lines naming only `Mathlib` or
  `Mathlib.*` modules (the plan's `imports`), the lemmas as declarations before the main
  declaration, the main declaration named `syndeom_s2_<producer>_<theorem>` with its proof as the
  concatenation of the steps' fragments. Both renderers are pure functions of the plan.

### D3 — Configuration (full, no defaults elided — SD1)

- **`s2_template`:** `{"theorem": <seed id>, "style": <style id of that seed>, "target":
  "informal" | "formal" | "pair", "flaws": [FlawSpec…], "padding_ratio": <non-negative number>}`.
- **`s2_grammar`:** `{"grammar": <grammar id>, "length": {"n_steps": <integer ≥ 1>, "n_lemmas":
  <integer ≥ 0>}, "target": …, "flaws": [FlawSpec…], "padding_ratio": …}`.
- **`FlawSpec`:** `{"class": "FLAW-NNNN", "sub_variant": <string or null, as the entry names>,
  "severity": <cosmetic | repairable | gap | fatal>, "site": "auto" | <step index>, "dials":
  {…the class's dials, D5, in full…}}`. `"auto"` lets the injector choose among the eligible sites
  with its labelled stream (D4); an explicit index must be an eligible site or the producer
  refuses (exit 2).
- The producer refuses (exit 2) any spec the target or the seed cannot realize (for example
  FLAW-0008 with target `informal`, FLAW-0009 with target `informal`, FLAW-0004 or FLAW-0010 with
  target `formal`, a `severity` outside the entry's range, or a sub-variant the entry does not
  name), any class outside FLAWS.md `0.1.0`, and any spec a grammar cannot realize (D6).
- A config that commands no flaw and zero padding is a **control**: a correct artifact
  (`ground_truth.flaws: []`, `proof_status: "valid"`). Every seed theorem and every grammar instance
  has its control; SD5's structured nulls (correct proofs of matched length, padded correct
  proofs) come from controls and from FLAW-0013-only configs of the same theorem or grammar.
- The config is the whole of what varies between artifacts of one producer version. Nothing else
  (no environment variable, no clock, no path) enters the bytes; the engine commit and the seed
  enter the manifest, never the proof text.

### D4 — The RNG: `syndeom-rng/1`

The definition below is normative; the published names are attributions. Everything is unsigned
64-bit, wrapping.

- **SplitMix64** step on a state `x`: `x ← x + 0x9E3779B97F4A7C15`; `z ← x`;
  `z ← (z ⊕ (z ≫ 30)) · 0xBF58476D1CE4E5B9`; `z ← (z ⊕ (z ≫ 27)) · 0x94D049BB133111EB`;
  output `z ⊕ (z ≫ 31)`.
- **Stream for a label.** A label ℓ is an ASCII string fixed by this ADR per module and instance,
  e.g. `injector/FLAW-0005/1`, `padding`, `grammar/plan`, `grammar/lemma/3`. Its stream seed is
  `seed ⊕ h(ℓ)`, where `h(ℓ)` is the first 8 bytes of SHA-256(ℓ) read big-endian (the manifest
  crate's `sha256_hex` supplies the digest). The stream state `s0..s3` is the first four SplitMix64
  outputs from that stream seed, and the stream is **xoshiro256\*\***: output
  `rotl(s1 · 5, 7) · 9`; then `t ← s1 ≪ 17`; `s2 ← s2 ⊕ s0`; `s3 ← s3 ⊕ s1`; `s1 ← s1 ⊕ s2`;
  `s0 ← s0 ⊕ s3`; `s2 ← s2 ⊕ t`; `s3 ← rotl(s3, 45)`.
- **Bounded draws** `below(n)` = `(next() · n) ≫ 64` in 128-bit arithmetic — fixed, loop-free, and
  the same on every platform. **No floating-point value ever enters a generation decision**: every
  dial is an integer, an enumeration or an exact rational held as an integer pair; `padding_ratio`
  is compared only after rendering, in `measure`.
- The set of labels a producer draws from, and the order of its draws, are part of its `rng`
  definition: a new label or a reordering bumps the producer's `version`. The master `seed` is the
  manifest's `seed` (ADR-0001 D4).
- **Conformance.** `engine/generate/tests/rng.rs` pins the first four outputs of the streams for
  seeds 0, 1 and 7 under the label `test`, computed at the implementation commit. Agreement with
  the published reference implementations of SplitMix64 and xoshiro256** is checked against
  vectors retrieved and recorded under SD11 at implementation if they can be retrieved; if they
  cannot, the definition above stands and the attribution is noted as unverified. Determinism
  (SD6) rests on this ADR plus the engine commit, not on the attribution.

### D5 — The dial schema: every FLAWS.md `0.1.0` recipe

Each class is a transformation of the plan with (i) the dials it exposes, (ii) what it does to
the informal and the formal file, (iii) the instance's `lean_catchable` and the predicted
`lean_build`, and (iv) the **confirmation check** that S2.2 requires. Two checks recur:

- **K (kernel):** `lake env lean` on the formal file exits non-zero **and** the first reported
  error (`<file>:<line>:<col>: error:`) lies within the line range of the recorded fragment —
  "rejects exactly as predicted". A failure elsewhere, or a pass, is a FAIL (a finding).
- **T (tooling):** the build passes; the audit tail (D8) prints `#print axioms` of the main
  declaration and the direct used-constants of every declaration in the file; the Rust side
  closes the used-constants relation over the file's own declarations and evaluates the
  class's condition.

Every record's `dials` object holds the spec's dials *after* site resolution — the resolved step
or line, every lexicon entry drawn, and the original text the recipe replaced or removed — so a
record is self-describing and the injection is reversible in principle (ADR-0001 D4).

| FLAW-0013 | `ratio` (the config's `padding_ratio`), `kinds` ⊆ {`restated-definition`, `re-derivation`, `unused-lemma`, `verbose-rewrite`}; severity `cosmetic`; positions drawn from the `padding` stream | whole steps or lemmas of true irrelevant material inserted at the drawn positions, one record per inserted paragraph with span `[0, len)` | matching unused declarations | informal records `NO`; formal records `YES-TOOLING`; `pass` | achieved `padding_ratio` within the commanded tolerance (D8), and T for the formal declarations |
| FLAW-0014 | `omitted_case` (the seed's or grammar's case id); `holds` ∈ {`true`, `false`} → severity gap / fatal | one branch of a complete case split deleted with every mention of it; the conclusion still asserted | the `rcases` / `cases` / `match` alternative deleted; Lean reports a missing case or an unsolved goal | `YES-KERNEL` / `fail` | K |

Notes to the table:

- **Location of a record** is the step and span of the changed, inserted or removed text (an
  omission point `[s, s]` for removed material, per ADR-0001 D3) and, for the formal file, the main
  declaration or the injected declaration at the fragment's first line. FLAW-0011 and FLAW-0012
  address step 0 (the statement) with span `[0, len)` and the main declaration at its statement
  line.
- **Several instances in one artifact** are applied in `instance` order, each on the plan the
  previous one produced; a later instance may not overlap an earlier one's span, and the producer
  refuses a spec whose sites cannot be made disjoint. A pair's two records of one instance share
  the `instance` number (ADR-0001 D4).
- **Severity** is the spec's value, checked against the entry's range and the recipe's own
  derivation (for example FLAW-0005 `violated` is `fatal`); a spec whose severity contradicts its
  dials is refused.
- **FLAW-0010 (b) and (c)** are deferred (Options, 5); a spec naming them is refused in v0.1.

### D6 — Seed theorems and grammars

**`s2_template` seeds.** A seed theorem is a data record `engine/generate/seeds/<id>.json`
(compiled into the binary with `include_str!`, so the emitted bytes are a function of the engine
commit): id; title; the informal statement; the faithful Lean statement with its imports; one or
more styles, each a list of aligned steps (text, fragment, premises, site kinds, the hidden-step
kind if the justification is deleted, the named theorem and hypothesis if one is applied); and the
recipe material the seed supports — drifted statements per FLAW-0008 transformation with their
proofs, the nearby false statement with its counterexample and hidden use site for FLAW-0012,
irrelevant lemmas and padding paragraphs for FLAW-0007 and FLAW-0013, false-step material for
FLAW-0004 `false` and FLAW-0010 `false`, violating objects for FLAW-0005, false lemma statements
for FLAW-0009 `false`. A seed declares which classes, sub-variants and severities it supports;
the producer refuses the rest.

The **v0.1 seed set** is the FLAWS.md `0.1.0` examples and ADR-0001 D8's theorem, every one of
them executor-authored synthetic material: `nat_le_sq` (Golden A/B; style `two_cases`),
`sq_plus_one_ge_two_x` (FLAW-0001), `continuity_is_not_uniform` (FLAW-0002),
`bounded_monotone_converges` (FLAW-0003), `rolle_abs` (FLAW-0005), `horses` (FLAW-0006; a false
statement), `bolzano_weierstrass` (FLAW-0008), `n_lt_two_pow` (FLAW-0009's helper),
`sqrt2_irrational` (FLAW-0011, FLAW-0013), `bounded_continuous_sup` (FLAW-0012),
`n_sq_mod_four` and `x_over_abs_x` (FLAW-0014), with FLAW-0004, FLAW-0007 and FLAW-0010 realized
on the seeds whose steps carry the material. Seeds whose mathematics needs real analysis are
admissible because Mathlib is pinned (ADR-0002 D2, ruling Q8). The set grows by later producer
versions; each new seed brings its goldens (D10).

**`s2_grammar` grammars (v0.1).** A grammar instance is a theorem *and* its faithful argument
generated from the `grammar/plan` stream, true by construction:

- `ring_chain` — polynomial identities over ℤ as a chain of `n_steps` equalities, each closed by
  `ring` inside a `calc` block; `n_lemmas` auxiliary identities proved separately and cited.
- `ineq_chain` — inequalities over ℝ chained from a fixed library of true atoms (squares are
  non-negative; two-term AM–GM; the triangle inequality), each step closed by `linarith`,
  `nlinarith` or `positivity`; hypotheses (for example a non-zero divisor) give FLAW-0005 its
  sites.
- `case_split` — statements over ℤ decided by residue or sign cases (`rcases`, `omega`,
  `decide`), giving FLAW-0014 its sites.
- `nat_induction` — sum and product identities over ℕ proved by `induction … with` and `ring`,
  giving FLAW-0006 its sites.

A grammar realizes, in v0.1: FLAW-0001, FLAW-0003 `cycle`, FLAW-0004 (`routine-true`,
`nontrivial-true`), FLAW-0005 (`ineq_chain`), FLAW-0006 (`nat_induction`), FLAW-0007 `unused`,
FLAW-0009 (`true` from a generated identity; `false` from a perturbed one), FLAW-0010 `a`,
FLAW-0011 (as the composite of the above), FLAW-0013, FLAW-0014 (`case_split`). The others
(FLAW-0002, FLAW-0003 `direct`, FLAW-0004 `false`, FLAW-0005 `violated`, FLAW-0007 `vacuous`,
FLAW-0008, FLAW-0012) need hand-authored mathematics and are `s2_template`-only until a later
grammar version adds them. The length dial is `length.n_steps` from 1 to 256 and `n_lemmas` from
0 to 32 in v0.1; the sweep's log-spaced grid is the S3 calibration ADR's to fix.

**Imports.** Each seed and each grammar declares the minimal `Mathlib.*` modules its fragments
need (`syndeom-lean/1` permits `Mathlib.*`); a bare `import Mathlib` is permitted but costs the
whole olean set per compile. The declared list is part of the plan and of the bytes.

### D7 — Ground truth by construction (SD1, SD12)

- `ground_truth.derivation` = `"by-construction"`; `taxonomy_version` = `"0.1.0"`; `flaws` = the
  records of D5 in `instance` order (empty for a control).
- `statement_status`:
  - a true seed statement: `method: "mathlib"` with the Mathlib declaration at the pinned commit
    when one states it, else `method: "lean-kernel"` with `reference` = the declaration in
    `lean/Syndeom/Seeds/<Seed>.lean` that proves it (a library module built by the gate; standard
    axioms checked by the gate's audit, D10);
  - a false seed statement (FLAW-0012, `horses`): `value: false`, `method: "lean-kernel"` with the
    declaration in the same module that proves its negation when the seed has one, else
    `method: "counterexample"` with the counterexample written out so it can be checked;
  - a grammar instance: `value: true`, `method: "lean-kernel"`, `reference` = `<artifact_id of the
    instance's control>:<main declaration>` — the control's `lean_build: "pass"` is measured and
    recorded in its own manifest (D8). This names a regenerable artifact's declaration rather than
    a module under `lean/`; ADR-0001 D4 constrains the reference's meaning, not its form, and the
    crate stores it as a string, so no schema string changes. Noted for Al in D12 as a
    clarification, not a decision Al must make.
  - `method: "undetermined"` never occurs in this family: every statement's truth is by
    construction.
- `proof_status`: `"valid"` iff every record is `cosmetic` (ADR-0001's consistency rule), i.e. a
  control, a FLAW-0013-only artifact, a FLAW-0007 `unused`-only artifact, or a FLAW-0004
  `routine-true`-only artifact; otherwise `"invalid"`. For a pair, `"invalid"` if either file's
  argument is invalid; FLAW-0008 makes a pair invalid although its Lean file builds. `correct` is
  derived by the crate.
- **Witness modules.** `lean/Syndeom/Seeds/<Seed>.lean` holds, per seed, the faithful statement
  with its proof, the negations the seed claims (FLAW-0012), and the unsatisfiability witnesses
  (FLAW-0007 `vacuous`); `lean/Syndeom.lean` imports them, so the gate builds them. They are small
  by design; the per-artifact harness (D8) compiles outside the library.

### D8 — Commanded, achieved, fidelity (S2.2)

- **Commanded keys** (ADR-0001 D4 registry; tolerances in ADR-0001 D6 forms):

  | Key | `s2_template` | `s2_grammar` | Tolerance |
  |---|---|---|---|
  | `n_steps` | the plan's step count after injection and padding | the same | `exact` |
  | `n_lemmas` | the plan's lemma count | the same | `exact` |
  | `n_flaws_total`, `n_flaws_<NNNN>` per class present | the number of records (per class) | the same | `exact` |
  | `flaws_confirmed` | the number of records | the same | `exact` |
  | `padding_ratio` | the config's `padding_ratio` | the same | `abs 0.05` (`abs 0.0` when the config's ratio is 0) |
  | `lean_build` (formal, pair) | `"fail"` iff some record in the formal file is `YES-KERNEL`, else `"pass"` | the same | `exact` |
  | `lean_axioms_standard` (formal, pair; only when `lean_build` is commanded `"pass"`) | `false` iff a FLAW-0009 record exists, else `true` | the same | `exact` |

  `n_tokens` is **achieved only** for both producers in v0.1 (the length command is in steps and
  lemmas; S3 bins by achieved tokens). The commanded block is a pure function of (config, seed)
  through the plan, as the manifest records both.
- **Achieved** values come from `syndeom-manifest`'s parsers on the rendered bytes
  (`informal_md_1_token_count`, `informal_md_1_step_count`, `informal_md_1_lemma_count`,
  `lean_1_token_count`, `lean_1_line_count`, `lean_1_declaration_count`), from the records
  (`flaw_0013_span_tokens_over_n_tokens`, `injected_instances_confirmed`), and from the Lean
  harness (`lake_env_lean_exit`, `print_axioms_subset_standard`); `ci95` is `null` throughout —
  nothing here is estimated.
- **The Lean harness** (`syndeom-generate` subcommand `verify`, also run by `generate` for every
  formal file before the manifest is written): from `lean/`, **one Lean process at a time**
  (machine hazard: each loads Mathlib's oleans), (1) `lake env lean <absolute path>` with exit
  code, stdout and stderr captured and `<file>:<line>:<col>: error:` lines parsed; (2) if it
  exits 0, a second file = the artifact's exact bytes + an **audit tail** that prints `#print
  axioms <main declaration>` and, for every declaration in the file, its direct used-constants
  (via `Lean.ConstantInfo.getUsedConstantsAsSet` in a `#eval` over `MetaM`), compiled the same
  way and parsed. The artifact's bytes are what is hashed; the audit file is derived, kept only
  under the sweep's evidence, and never stored under `corpora/`. One JSON-lines evidence file per
  sweep run records, per artifact, the exit code, the first error location, the axiom list and
  the used-constants closure (D10 says where).
- **Fidelity**: `fidelity.per_statistic` and `verdict` by ADR-0001 D6 (`statistic_verdict`,
  `fidelity`). A `FAIL` artifact is written with its verdict, counted by nobody (ADR-0001 D9), and
  listed in the sweep report as a finding with the failing statistics named; it is never deleted
  or regenerated under a different seed to make a grid cell pass.
- **The fidelity sweep** (Gate S2's first criterion) runs every v0.1 seed and grammar over every
  spec it supports, every target, and a fixed seed list, writes the artifacts under `corpora/`,
  the evidence under `analysis/s2-fidelity/evidence/`, and a report
  `analysis/s2-fidelity/report.md` with its JSON (commanded versus achieved per class × producer ×
  target × severity; confirmation rate; every FAIL), regenerable from a fresh clone by one
  command. The tolerances are the table's; the length grid is the S3 ADR's. Its cost is dominated
  by the per-artifact Lean compiles and is measured, not predicted, in the report.

### D9 — Manifests and determinism (S2.3)

- Every artifact directory `corpora/<artifact_id>/` holds `manifest.json` (`syndeom-manifest/2`,
  `origin: "synthetic"`, `generator {id, version, rng: "syndeom-rng/1"}`, the 40-hex
  `engine_commit`, the integer `seed`, the full `config`, `config_hash` by JCS, `toolchain` read
  from `lean/lean-toolchain` and `lean/lake-manifest.json` when a formal file exists, `artifact`
  with `storage: "regenerable"` for every file (ADR-0002 D7), `ground_truth` per D7, `commanded`,
  `achieved` and `fidelity` per D8) and, until the directory is committed, the proof files; the
  manifest is committed, the proof bytes are regenerated and verified by `content_hash`
  (`.gitignore` already excludes them). `artifact_id` is ADR-0001 D2 with the `-s<seed>` segment.
- **`engine_commit`** is verified as `syndeom-derive` does: the named commit's blobs for the
  producer's tracked input set — `engine/generate/**`, `engine/manifest/**`, `engine/Cargo.toml`,
  `engine/Cargo.lock`, `rust-toolchain.toml`, `lean/lean-toolchain`, `lean/lakefile.toml`,
  `lean/lake-manifest.json`, `lean/Syndeom/Seeds/**` — equal the working-tree bytes, and the
  commit is an ancestor of `HEAD`; otherwise refusal (exit 2).
- **The id invariant** (S2.3, FRIEDMAN's corpus-id invariant with `artifact_id`): tested, not
  asserted — (i) generating the same (config, seed) twice in two processes yields byte-identical
  files and manifest; (ii) `syndeom-generate regenerate --manifest <path>` re-emits from the
  manifest's `config` and `seed` and reproduces every `content_hash`; (iii) two artifacts with the
  same id are byte-identical (the producer refuses a same-id conflict with exit 3, like
  `syndeom-ingest`); (iv) the bytes are the same on Windows and Linux (LF always; no
  platform-dependent formatting; the advisory CI, which runs the gate on `ubuntu-latest`, runs
  the determinism tests too).
- **CLI**, following the house pattern: `syndeom-generate generate --config <config.json> --seed
  <u64> --root <repo root> --engine-commit <40-hex> [--dry-run]`; `syndeom-generate regenerate
  --manifest <path> --root <repo root>`; `syndeom-generate verify --artifact <dir> --root <repo
  root>` (the harness alone, writing evidence, never a manifest); `syndeom-generate sweep --grid
  <grid.json> --root <repo root> --engine-commit <40-hex> --evidence <new directory>`. Exit codes:
  0 written or identical; 1 usage or I/O; 2 refused (self-check, unsupported spec, commit
  mismatch); 3 same-id conflict. A failed confirmation is **not** a refusal: the artifact is
  written with `verdict: "FAIL"` and exit 0, and the verdict is printed.
- **Receipts:** every `generate`, `verify` and `sweep` run writes a receipt (schema
  `syndeom-generate-receipt/1`: the command, the producer and its version, the engine commit, the
  toolchain, every Lean command with its exit code and timing, and the artifact ids written) into
  a new directory that is never overwritten (`syndeom-pair`'s rule).
