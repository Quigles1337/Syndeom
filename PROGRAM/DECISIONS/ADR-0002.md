## Options considered

- **Lean/Mathlib pin.** (a) Mathlib master tip — rc toolchain, moves daily, the pin would be
  arbitrary within a day. (b) **The newest Mathlib release tag whose `lean-toolchain` is a stable
  (non-rc) Lean release** — chosen: a release tag is a named, stable point with a cache, and the Q8
  rule "Lean follows Mathlib" then yields a non-rc Lean. (c) Match KOBER's v4.33.1 — Mathlib has a
  `v4.33.1` tag, but it is two releases older with no reason beyond sibling symmetry, and Q8 already
  records the divergence as load-bearing. (d) Match the S5 contact corpus's pin — **not a
  criterion** (SD8: contact material never informs design). Criterion (b) was fixed before the tag
  list was read; the fact that it selects the same commit the first contact corpus pins (S-0001) is
  disclosed in the Session-4 LEAKAGE CHECK as a coincidence of dates, not a reason, and would be
  the same choice if that corpus did not exist.
- **JCS serializer.** `serde_json_canonicalizer 0.3.2` (FRIEDMAN ADR-0002 D4 precedent; MIT;
  enables `float_roundtrip`; formats numbers with `ryu-js`) — chosen, on the condition, now met
  (D8), that it passes the RFC 8785 vectors from S-0007 in this repository's own tests.
  `serde_jcs` and `jcs-canonicalize` exist on crates.io and were not evaluated beyond that.
- **Golden B as a project module or a loose file.** A module (`lean/Syndeom/Fixtures/GoldenB.lean`,
  byte-identical to ADR-0001 D8) — chosen: `lake build` then builds it as part of the library, and
  an engine test pins the module's bytes to the fixture so the two cannot drift.
- **Synthetic storage default.** `regenerable` (manifests committed; proof files regenerated from
  the manifest and verified by `content_hash`; FRIEDMAN ADR-0002 D3 precedent) versus `committed`.
  `regenerable` — chosen: a calibration grid is thousands of small files whose bytes are a pure
  function of the manifest; the content hash makes either choice verifiable, and fixtures that
  must be in the tree live under `engine/manifest/tests/fixtures/`.
- **Register check location.** The cross-reference script the executor had been running from its
  scratchpad moves into `scripts/` so a fresh clone carries the whole gate.

## Decision

### D1 — Lean toolchain pin

`lean/lean-toolchain` is the single line `leanprover/lean4:v4.34.1`, copied from Mathlib's
`lean-toolchain` at the D2 commit. Rule (Q8): the Lean version is whatever the pinned Mathlib
commit's `lean-toolchain` says, never chosen independently; a change of either is one ADR
transition that changes both and re-reads S-0008. elan installs the toolchain on first use inside
`lean/` (it did so in Session 4 from `releases.lean-lang.org`).

### D2 — Mathlib pin and dependency lock

`lean/lakefile.toml` requires `mathlib` from `https://github.com/leanprover-community/mathlib4` at
`rev = "d13f23b723b8a846827a245b89c10fc7d3f11612"` (tag `v4.34.1`). `lean/lake-manifest.json` is
committed and locks Mathlib's eight transitive Lake dependencies at the revisions Mathlib's own
manifest named at that commit: `batteries` `f2effa3d803f`, `aesop` `355695d523e4`, `Qq`
`6a489d9af5d0`, `proofwidgets` `106ff4fafc74`, `importGraph` `e928b7254487`, `LeanSearchClient`
`ddf04cf3949f`, `plausible` `118aa17ee846`, `Cli` `e92c9f15fdfa`. Mathlib's compiled modules come
from `lake exe cache get` (8,908 files for this commit); the gate builds only this project's
modules. Licences: S-0008 (all Apache-2.0 except `Cli`, MIT).

### D3 — Lean project layout

`lean/lakefile.toml` (package `syndeom`, library `Syndeom`, default target `Syndeom`);
`lean/Syndeom.lean` (library root, imports the fixtures); `lean/Syndeom/Fixtures/GoldenB.lean`
(**exactly the ADR-0001 D8 Golden B bytes**, SHA-256 `c568a981…458e`, pinned by the engine test
`d8_lean_project_module_is_the_golden_b_bytes`); `lean/Audit.lean` (not a library module; run by
the gate as `lake env lean Audit.lean` to print `#print axioms syndeom_golden_nat_le_sq`). `.lake/`
is ignored. Future S1.2/S2 Lean fixtures are modules under `lean/Syndeom/`.

### D4 — Rust toolchain and workspace

`rust-toolchain.toml` at the repository root: channel `1.91.0`, components `["clippy", "rustfmt"]`
(Q6; FRIEDMAN's set, a superset of KOBER's). `engine/Cargo.toml` is the workspace root (Q7),
resolver 3, member `manifest`. Crate `syndeom-manifest` 0.1.0, edition 2024, `publish = false`,
`#![forbid(unsafe_code)]`, implementing ADR-0001 D1–D7 (types with `deny_unknown_fields`;
`required_option` so nullable fields must be present; `artifact_id` in both forms; the
`syndeom-informal-md/1` segmenter and `syndeom-lean/1` counter; code-point spans; the D6 verdict
rule; `Manifest::check` with every D4 consistency rule; `Manifest::check_derived` for the
derived-canonical-artifact convention). Direct dependencies: `serde 1.0.229` (derive),
`serde_json 1.0.154` (`float_roundtrip`), `serde_json_canonicalizer 0.3.2`, `sha2 0.11.1`,
`hex 0.4.3`; `engine/Cargo.lock` committed (24 crates; licences S-0008).

### D5 — JCS serializer

`serde_json_canonicalizer 0.3.2` is the RFC 8785 serializer behind `config_hash` and
`prompt_hash`. `engine/manifest/tests/goldens.rs` holds, transcribed from the retrieved RFC
(S-0007), the §3.2.2 sample input with the §3.2.4 expected bytes, all 24 finite Appendix B rows,
the NaN/Infinity error rule, and a UTF-16 property-sorting case; the ADR-0001 D8 goldens and the
FRIEDMAN ADR-0004 seven vectors sit beside them. If the crate ever disagrees with a vector, the
crate is replaced, not the vector.

### D6 — The gate and CI

`scripts/check.sh` (SD9): `lake build` in `lean/`; the axiom audit of the golden fixture (the
printed axiom set must be within `propext`, `Classical.choice`, `Quot.sound`); `cargo fmt --all
--check`; `cargo clippy --all-targets --all-features -- -D warnings`; `cargo test`; the
line-ending check (`git ls-files --eol` shows no `i/crlf`, `i/mixed`); `scripts/check_registers.py`
(stdlib Python: byte-level CR/BOM/trailing-LF check of every tracked text file and the Q/SD/FLAW/
CLAIM/S- cross-reference check). Exit 0 prints `GATE: GREEN`. "Green default branch" now means
this script exits 0 on the default branch.

`.github/workflows/check.yml` runs the same script on `ubuntu-latest` on pushes to `main` and on
pull requests: `actions/checkout@v5`, `actions/cache@v5` on `lean/.lake` keyed by `lean-toolchain`
+ `lake-manifest.json`, elan from `elan-init.sh`, `lake exe cache get`, rustup reading
`rust-toolchain.toml`. It is advisory and is **never a required status check** (Q9); the gate's
authority is the local run recorded in STATE.md.

### D7 — Storage default, directories, ignore rules

Synthetic proof files default to `storage: "regenerable"` (ADR-0001 D2 enum): `.gitignore` ignores
`corpora/**/proof.md` and `corpora/**/Proof.lean`; `manifest.json` is always committed; ground-truth
and contact files follow their licences (`committed` or `external`). Directories per §3.8 (Q17):
`lab/` (README: zero result authority, SD10), `corpora/`, `groundtruth/`, `contact/` (README posts
the SD8 rules, including `ground_truth: null` and the derived-artifact convention), `analysis/`,
`sources/` (exists since S0.1), `scripts/`. `.gitignore` also ignores `.lake/` and `engine/target/`.

## Consequences

- S0.6 exit criteria ("scaffold" and "repo green under the gate") are satisfied by this ADR and
  the files it lands; from this commit "green" means `scripts/check.sh` exits 0.
- A toolchain change is one ADR transition that touches `lean/lean-toolchain`, the `lakefile.toml`
  rev, `lake-manifest.json`, `rust-toolchain.toml` or `Cargo.lock` as applicable, and S-0008.
- S5 contact corpora carry their own pins (constitution S5.1). The first corpus's pin coincides
  with D2 today; S5 ingest still records each corpus's pins from its own files and does not rely
  on the coincidence.
- The advisory CI downloads Mathlib's cache on every cold run (`actions/cache@v5` keyed on the two
  pin files reduces repeats); its result never gates a merge.
- S1.2 and S2 Lean fixtures are modules under `lean/Syndeom/`; the gate builds them all. A fixture
  that is *meant* to fail (YES-KERNEL flaws) cannot be a library module and must be built by its
  own harness in S2 (`lake env lean <file>` with the expected failure asserted) — an S2 ADR item.
- Machine hazards learned here (lake's silence under a pipe, `.lake` measurement during unpack)
  are recorded in the executor's memory as hazards, not as state.
