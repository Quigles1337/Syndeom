## D1 — Supported input and exact transformations

Input is exactly one gzip member containing at most 16 MiB of non-NUL TeX source bytes.
Tar archives, multiple gzip members, trailing bytes and binary containers are refused.
`flate2` 1.1.10 is pinned, using its safe Rust default backend; existing dependency versions
and Lean/Rust pins stay fixed. The new dependency closure is recorded with verification.

The entire decompressed source is emitted **unchanged** as required external `context.tex`.
It is opaque bytes: the selected real source has legacy non-UTF-8 bytes in its bibliography.
Only selected statement and proof slices are required to decode as UTF-8, strictly; there
is no replacement decoding, Unicode normalization, TeX evaluation, rendering or macro expansion.

A reviewed recipe names one unique `\label{...}` immediately after the opening of a
`proposition`, `theorem` or `lemma` environment. Its end must be followed, apart from whitespace,
by `\begin{proof}`. The recipe's statement range must cover the entire statement body.
Ordered proof ranges cover every non-whitespace byte through `\end{proof}` and distinct steps
must be separated by an original paragraph boundary (at least two LF characters).
Text cannot be silently skipped, duplicated, reordered or added.

The only body transformation (`ascii-whitespace/1`) trims and collapses ASCII space, tab,
CR and LF runs to one space. A step cannot swallow an internal blank line. Selected text
with comments, explicit linebreaks, environment boundaries, macro definitions, verbatim,
input/include, category-code manipulation or the other control constructs listed in the
implementation is refused. Unsupported source forms need a new reviewed procedure, not
silent conversion. This is a deliberately restricted lexical extraction, not a complete TeX parser.
Its checks supplement a human-readable source-fidelity review; they do not decide TeX semantics.

The title is a reviewed metadata label. The canonical `**Theorem.**` marker identifies the
statement slot regardless of the source environment's name. `**Step k.**` labels wrap the
reviewed segments; they do not supply a missing inference. TeX notation, references, citations,
spelling, hypotheses, conclusions and mathematical mistakes inside those segments remain literal.

## D2 — Context, segmentation and locations

The recipe pins compressed parent bytes via the parent manifest, the exact parent manifest's
SHA-256, the full decompressed context hash, every selected byte range and its SHA-256.
Four required context roles (`preamble`, `definitions`, `prerequisite`, `bibliography`) pin
the reviewed blocks. The preamble and bibliography must be complete. All other source
context remains available because the companion retains the entire source, including macros,
definitions, prior remarks, references and original numbering. No cited external theorem is
silently imported or claimed checked. A reader must retain/access `context.tex` with `proof.md`.
The artifact is canonical textual data, not a standalone rendered or executable TeX document.

For the selected example the original one-paragraph proof becomes one step. No clause-level
segmentation or added lemma is needed. Counts and span checks come from the existing
`parse_informal_md` and `span_text` functions. Source offsets are half-open **bytes** in
decompressed source; canonical spans are half-open **Unicode scalar indices** in marker-free
step text. Step 0 is the statement. Recipe mappings bind each parent's flaw instance in order
to one valid, nonempty step/span and a hash of its selected text. This first version does not
support omission-point mappings.

The written item review must justify location precision. For a statement-wide composite flaw
whose source names the proposition without a failing proof step, anchoring the whole statement
does not assert that the source identified a narrower defect. The source-map preserves the raw
locator and the RECORD explains the entire affected proof's relationship to that anchor.
Every other flaw field, including instance IDs and dials, is preserved exactly.

## D3 — Configuration, validation, provenance and output

The config inherits `sources`, `item`, `licence`, `status` without modification and adds
`derived_from`, `method`, the full versioned recipe and external context metadata. JCS config
hashing, artifact IDs, manifest serialization and canonical counts use `syndeom-manifest`.
Both `Manifest::check` **with actual bytes** and `Manifest::check_derived` run on every result.
An additional equality check restores original locations then compares all ground truth, so
instance IDs, order and dials cannot drift beyond the ratified validator's multiset check.
Mechanical syntax checks and the empty-statistics fidelity PASS are not transcription or
mathematical correctness certificates.

Commit the tested producer before generating a real manifest. Its actual 40-hex commit is
`engine_commit`. The CLI checks the tracked Rust producer, manifest library, dependency lock
and toolchain inputs against that commit. Fixtures use an explicitly artificial all-zero
commit only through the library; the real CLI refuses a non-producer commit.
Artifact/evidence commits follow the producer commit; identical reproduction preserves its
engine commit rather than substituting current HEAD.

Version 0.1.0 always stores source-derived bytes **external**, even for a parent whose rights
could allow more. The repository gets manifest, offsets, hashes, configuration and review
metadata; the explicitly chosen external directory gets `proof.md` and full `context.tex`
under the child ID. This implements the selected parent's existing non-exclusive-arXiv
rights decision, not new redistribution permission. No restricted source excerpts are added.

All output destinations are preflighted before any writes. Existing identical files permit
an idempotent retry; same-ID/different-bytes files are refused. New writes use exclusive create,
never truncation. A crash may leave a partial set; complete files with missing siblings allow
an identical retry, but incomplete files are conflicts requiring a new destination or separately
reviewed recovery. Multi-file atomicity is not claimed. Redirected artifact directories are refused. `--dry-run` validates
and reports without writing.

## D4 — Verification and acceptance

The artificial fixture exercises two steps, a lemma, multibyte Unicode, canonical byte/count
rules, fixed hashes/IDs/serialization, linkage and independent regeneration. It is test data,
never a real corpus item. Negative cases cover changed source/parent bytes, ambiguity,
missing context, omissions, unsupported transformations, invalid spans, inherited metadata
changes, and output conflicts. Existing manifest/ingest goldens are unchanged.

The real slice requires fresh primary retrieval and byte verification (SD11/SD16), a
source-fidelity/location review, byte-aware checks, parent/child checks and regeneration with
byte-identical outputs. The final repository gate uses existing pinned Lean/Mathlib/Rust.
Actual commands and logs belong to the new S1.3 evidence directory and are distinguished from
historical gate evidence. No gate closure, PROVEN status, cold-start pass or performance claim
follows from this procedure.
