# ADR-0009 — Constitution amendment, SD15 and §6: memory disclosure first in every session launched with the Session-N resume prompt

- **Date:** 2026-10-26 UTC (Session 26, an informed working session from `main`
  `3cd5558223294571dd85164eb0d2730cb1911637`, tree `125b1ed56d8dcab8074119eb51fc3467dbb09dda`, on
  branch `claude/s1-adr-0009-disclosure-first`).
- **Status:** **accepted — Al's acceptance of 2026-10-26, with rulings 1–4 and additions 5–6, and
  Al's ruling of the same day choosing option 1 after the gate failed on the text first
  accepted**, both transcribed verbatim below (*Owner direction and acceptance*). Approved as a
  constitution amendment under §3.5. The executor drafted the text; every choice the draft left
  open was ruled by Al.
- **Scope:** when the SD15 memory disclosure is made and by which sessions; how it is appended;
  the §6 Session-N resume prompt; ADR-0008 D1 step 0 and the wording that follows from it; and one
  line of the S1.3 reproduction tool (D5). It changes nothing about what memory may hold, what the
  disclosure contains (ADR-0005 D1–D3), the exam's pass criterion, the conversation-context
  corollary, the gate script, any register or any frozen packet. It is not retroactive: Sessions
  22 and 25 remain ineligible attempts.

## Context

- SD15 bound "any session attempting a gate's cold-start test" to disclose "before any other
  action". ADR-0008 D1 step 0 let an examination read only the constitution and ADR-0005 before
  disclosing. Whether a session *is* an examination was recorded only in STATE's
  NEXT-SINGLE-ACTION and in ADR-0008, which a session may not read before disclosing. A fresh
  executor could not learn that it was the examination without making itself ineligible to be one.
- Session 25 (HANDOFF Session 25) was launched as the Gate S1 examination with the §6 prompt
  verbatim and alone. It ran commands and read STATE, HANDOFF and ADR-0008 before disclosing, and
  is ineligible. It also ran a command before reading the constitution at all, so a rule in the
  constitution's body does not reach an executor in time on its own: the instruction has to be in
  the launch prompt, the one text read before anything else.
- Session 25 escalated three options (STATE, Standing escalations): (a) amend SD15, (b) amend the
  §6 prompt, (c) no amendment. Al directed both (a) and (b), and ADR-0008 D1 step 0 beyond
  examinations.
- A disclosing session that follows the old prompt and §4.1 literally would still fail one step
  later: §4.1 opens with `git status` and `git log` before any fetch, and a file-editing tool
  reads HANDOFF (program state) before appending to it. The prompt therefore also points to
  ADR-0008 for orientation (ruling 3) and says how to append (addition 5), and the block header
  may be provisional because the session number is unknown before orientation (addition 6).
- **Reproduction cost, measured before the draft.** The S1.3 effective-inventory reproduction
  (`engine/ingest/examples/s1_effective_inventory.rs`, packet
  `analysis/s1-first-parent-integration/`) checks every file of its accepted baseline at `HEAD`
  byte for byte, except the named summaries `README.md` and `PROGRAM/STATE.md` and the
  prefix-preserved `PROGRAM/HANDOFF.md`, ADR-0003 and `groundtruth/README.md`. In a scratch clone
  on 2026-10-26: at main `3cd5558` it printed `PASS: 35 archived representations / 32 effective
  logical items` with `inventory.json` byte-identical to the retained one (SHA-256
  `b626d1b5…1b803`); with one word of the constitution changed it failed `historical bytes
  changed: PROGRAM/SYNDEOM-PROGRAM.md`; with one word of ADR-0005 changed it failed the same way on
  ADR-0005. ADR-0008 is not in that baseline. Without a change to the tool (D5), any amendment of
  the constitution's bytes ends that reproduction's ability to run on main, the cost Al's
  decision 2 of 2026-10-21 avoided by giving
  ADR-0008 the addendum form.
- **The gate failed on the text first accepted, because ruling 1 rested on a wrong premise.**
  Ruling 1 accepted the break, kept the tool unchanged and pinned the reproduction to `3cd5558`,
  on the premise that the gate was unaffected because the cargo tests that check historical
  bytes use in-memory fixtures. In Al's words, "I saw the test mutate its blobs in memory and
  missed that its fixture loads the frozen baseline from the working tree": the fixture of
  `engine/ingest/tests/first_parent_amendment.rs` reads the 375 baseline files from the working
  tree and runs the same `preserve()` check as the reproduction. The executor's draft had missed
  the same test, having looked for such tests only under `examples/`. The full gate on the staged
  tree (2026-10-26T20:16:14Z–20:16:51Z, nothing committed) failed in `cargo test`: 4 of that
  suite's 15 tests returned `historical bytes changed: PROGRAM/SYNDEOM-PROGRAM.md`. With
  `--no-fail-fast` those four were the only failures; with the constitution restored, all 82
  tests passed. The executor offered four options — (1) a one-line tool fix, (2) a frozen copy of
  the old constitution beside the test, (3) narrowing the tool's byte checks to the inputs it
  depends on, (4) withdrawing the amendment — and Al chose (1); D5 records it.
- Leakage (SD8): nothing here touches contact material, a detector or a design decision.

## Options considered

1. **No amendment** (Session 25's option (c)) — rejected: the next attempt would depend on an
   inference that two attempts did not make.
2. **SD15 only** (option (a)) — insufficient alone: Session 25 acted before reading the
   constitution, so a rule in its body can come too late.
3. **The §6 prompt only** (option (b)) — insufficient alone: SD15 would still scope the disclosure
   to a session attempting a gate's test, which a fresh session cannot determine in time, and
   ADR-0008 step 0 would still say "examination only".
4. **SD15, the §6 prompt and ADR-0008 step 0 together** — **chosen**.
5. **Keep the constitution's bytes and put the instruction elsewhere** — not available: the only
   texts a fresh session reads before acting are the launch prompt and the constitution, and the
   prompt is constitution §6 by SD15's own words.

## Decision

- **D1 — SD15.** Every session launched with the §6 Session-N resume prompt, whether or not it
  will attempt a gate's cold-start test, makes the memory disclosure the first entry of its
  HANDOFF block, before any action except reading the constitution and ADR-0005 in full and
  reading and hashing the memory it reproduces. A session that reads program state before
  disclosing — any repository file but those two, a listing of the checkout's directories, Git
  history or status, or a build — cannot be an examination. The disclosure's content is ADR-0005
  D1–D3, unchanged. (Rulings 2, 3 and 4.)
- **D2 — The §6 Session-N resume prompt** opens with that instruction as its first sentence, says
  how to append it (D6) and under what header (D7), and then points to ADR-0008 D1 for orientation.
  The new text is the verbatim launch. (Ruling 3; additions 5 and 6.)
- **D3 — ADR-0008 D1 step 0** applies to every session launched with the §6 Session-N prompt, not
  only an examination (ruling 2). After disclosing, a session may read ADR-0008 and nothing else
  of the checkout before step 5. Executor memory is not written until the session has established
  that it is not an examination; an examination writes none. Step 4 and D3's first two bullets say
  "session" where they said "examination", because every disclosing session now has the same
  declared HANDOFF append. Step 0's list of what may not be read gains directory listings, the
  same definition as D1.
- **D4 — Records of the constitution's SHA-256.** Records of the *current* constitution (STATE)
  are updated to the amended digest. Records of a past baseline — HANDOFF entries (append-only),
  ADR-0008's header (a fact about that ADR) and the frozen evidence packets under `analysis/` —
  stay byte-identical; ADR-0008 gains an *Amendments* entry naming both digests. The complete list
  is in *Consequences*.
- **D5 — The S1.3 effective-inventory reproduction tool treats the constitution as a document
  that legitimately changes** (Al's ruling of 2026-10-26, option 1, replacing ruling 1's "the tool
  is not changed"). The constitution changes only by ADR, so it never belonged in a
  data-reproduction byte check. `preserve()` in `engine/ingest/examples/support/effective.rs` now
  skips `PROGRAM/SYNDEOM-PROGRAM.md` beside `README.md` and `PROGRAM/STATE.md`, with a one-line
  comment citing this ADR; nothing else in the tool changed. That source file's SHA-256 was
  `516bd44e20a73259f7577ffd6a41230d99141d33ca16147d0b0b7719eea99775` (the value in the retained
  provenance's `tool_source_sha256`) and is now
  `92a816bcc7cf02acec98bcda1fc7775444f331aede1ca9786c23d750d4dcb30c`; the entry point
  `engine/ingest/examples/s1_effective_inventory.rs` (`83a28119…c667`), the preservation inputs,
  the test file and the packet are unchanged. Reproduced at main
  `3cd5558223294571dd85164eb0d2730cb1911637` with that revision's tool, the retained
  `inventory.json` stays byte-identical (SHA-256 `b626d1b5…1b803`). At this amendment's tree the
  reproduction passes (`PASS: 35 archived representations / 32 effective logical items`), and its
  output differs from the retained one only in `preservation.exact_files_checked`, 370 → 369,
  because the constitution is no longer counted among the exact files (output SHA-256
  `df3a2c7f…a7f5`). The gate is green with the fix (*Consequences*). Narrowing the tool's byte
  checks to the inputs it depends on remains a non-blocking note in STATE, done for the
  constitution only.
- **D6 — Appending without reading** (addition 5). The disclosure is appended to
  `PROGRAM/HANDOFF.md` without reading its existing contents — a shell append or a script, not a
  file-editing tool that reads a file before changing it — because HANDOFF's earlier entries are
  program state. Stated in the prompt and in ADR-0008 step 0.
- **D7 — Provisional block header** (addition 6). The new block may begin with a provisional
  header (the UTC date, marked provisional), completed after ADR-0008 step 5 without changing the
  disclosure text; the header is not part of the disclosure. Stated in the prompt and in ADR-0008
  step 0.

This is an informed session for SYNDEOM, not a cold-start examination. Do not attempt or certify Gate S1.

Show me the exact before/after text of each change. Change nothing until I accept. After I accept: apply the amendments with the constitution's amendment note updated; record the ADR; find and update every place that records the constitution's SHA-256; update STATE and HANDOFF; run the gate; open a PR; and stop for my review.
