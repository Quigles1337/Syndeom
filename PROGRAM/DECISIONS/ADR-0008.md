## Context

§4.1 ORIENT, as written, begins with three local commands:

```
git rev-parse --show-toplevel && git remote -v      # confirm which repo this is
git status && git log --oneline -20                  # confirm actual recent history
git symbolic-ref refs/remotes/origin/HEAD            # discover default branch (SD7)
```

None of them contacts the remote. `git status` compares the checked-out branch with the
*remote-tracking ref as of the last fetch*, so `## main...origin/main` with no ahead/behind count
means "equal to what this checkout last fetched", not "equal to the remote". A checkout left
idle while others push looks synchronized until someone fetches.

That is what happened on 2026-10-21 (HANDOFF Session 22). A session launched with the §6
Session-N resume prompt verbatim and alone — the launch the then-current NEXT-SINGLE-ACTION had
asked for — ran §4.1 on `C:\Users\LEET\Syndeom`, whose `origin/main` ref had not been fetched
since Session 20 (2026-10-14). Every §4.1 check passed and the gate was GREEN at `8e222a4`, while
`origin/main` was 24 commits ahead (PRs #1–#8, merged by Al 2026-10-19..21: README, ADR-0006,
ADR-0007, the frozen S1.4 coverage, the first-parent status amendment, the readiness
reconciliation whose NEXT was the Gate S1 cold-start examination). The session reconstructed the
Session-20 state, executed the Session-20 NEXT (the tenth harvest), and learned of the
divergence only when `git push` was refused. The harvest is held on branch
`claude/s1-harvest-candidates-28-30` at `c3a3d369689d56bab3678f519904087b313daf4e` (Al's
decision 1). Two executors now write to this repository from different checkouts on the same
machine; other checkouts may hold unpushed local work, and this procedure never reaches into
them.

"State files are claims; builds are evidence" (§4.1) already names the hazard for STATE.md. A
checkout's remote-tracking ref is a claim of the same kind, and a GREEN gate on a stale tree is
evidence about the stale tree only.

## Options considered

1. **Amend §4.1's text** (a `git fetch` line and a divergence clause). Rejected for this task by
   Al: the constitution's bytes are part of the accepted preservation baseline, and a text
   amendment is the heavier instrument; this ADR records the text such an amendment would adopt.
2. **A STATE note only** ("Fetch first", written in Session 22). Insufficient on its own: STATE is
   read *after* the commands it would correct, it binds no one, and it leaves no receipt.
3. **An accepted ADR with the complete procedure, an executable preflight that writes a receipt,
   and offline verification of the failure mode** — chosen. The preflight is standard-library
   Python with zero result authority (SD10); the historical build gate does not call it, so the
   gate acquires no network dependency.

## Decision

### D1 — The amended §4.1 procedure (complete; binding in this order)

Step 0 applies to an examination only; steps 1–7 apply to every session.

0. **Examination only — SD15 disclosure first.** Before any orientation command, reproduce the
   recalled memory as the first substantive entry of the new HANDOFF block, as SD15 and
   ADR-0005 require. The constitution and ADR-0005 may be read from the checkout before the
   fetch because they are frozen files; step 5 confirms that the snapshot's copies are
   byte-identical to what was read. Nothing else of the checkout (STATE, earlier HANDOFF entries,
   registers, builds, Git history) is read before step 5 completes. Write no executor memory.
1. **Identity.** `git rev-parse --show-toplevel`; `git remote get-url origin` must be the remote
   STATE records (`https://github.com/Quigles1337/Syndeom`); record both. A different checkout
   or remote is not this program's repository.
2. **Fetch.** `git fetch --prune origin`. Record the exit code and the UTC start and end. **On
   failure, stop:** there is no current snapshot, no program state is reconstructed, and no
   cached NEXT is executed from this checkout; the session records the failure and ends clean.
3. **Default branch.** Discover it: `git ls-remote --symref origin HEAD`; fallback
   `git symbolic-ref refs/remotes/origin/HEAD`; repair `git remote set-head origin -a` (SD7).
   Record the name and its source. Never assume `main`.
4. **Snapshot and checkout identification.** Record: the fetched tip
   `refs/remotes/origin/<default>` as a full SHA with its tree; `HEAD` as a full SHA with its
   tree and branch (or detached); the working-tree status (`git status --porcelain`), with the
   examination's own HANDOFF append the only change an examination may declare expected; the
   ahead/behind counts (`git rev-list --left-right --count HEAD...origin/<default>`); and the
   local-only and remote-only commit lists. State the classification: synchronized, behind,
   ahead, or diverged, and whether unrelated changes exist.
5. **Selection.** Exactly one of:
   - *synchronized, no unrelated changes* — the checkout is the snapshot;
   - *behind only, clean apart from declared paths, on the default branch* — synchronize by
     fast-forward only (`git merge --ff-only origin/<default>`), then re-verify that `HEAD` equals
     the fetched tip and the tree is still clean;
   - *ahead, diverged, unrelated dirty work, or a refused fast-forward* — change nothing in the
     checkout; create an isolated worktree at the fetched tip
     (`git worktree add --detach <dir> origin/<default>`), verify its `HEAD`, and examine there.
     Ahead and diverged commits stay on their branches; unrelated dirty work stays where it is.
   Record the examined checkout (path, full SHA, tree). Then confirm that the constitution bytes
   read in step 0, if any, equal the snapshot's.
6. **Reconstruct from the examined checkout only.** Continue §4.1 as written — STATE →
   HANDOFF's last entry → CLAIMS → FLAWS → the relevant DECISIONS, then the gate — in that
   checkout. The session's HANDOFF entry records the step 1–5 facts: remote, fetch result and
   time, fetched SHA and tree, examined SHA and tree and path, status and classification. An
   examination's record states the fetched `origin/<default>` SHA it reconstructed from.
7. **Before publication.** Immediately before any push or pull request, re-fetch and compare the
   target with the baseline the work was built on. If the target moved, stop: re-orient on the
   new tip (steps 2–6) and integrate deliberately — a fast-forward, or a rebase or merge of
   commits that have been read — never blindly. A diverged local commit goes to a branch.

**Prohibited throughout:** `git push --force` in any form; `git reset --hard`, `git checkout --`,
`git clean` or any other command that discards work that is not this session's own and declared;
merging anything but a fast-forward in step 5; executing a cached NEXT, or any task text that
carries a NEXT, without a successful fetch and a selected snapshot.

### D2 — The executable preflight and its receipt

`scripts/orient_preflight.py` performs steps 1–5 and step 7 and writes a JSON receipt
(`syndeom-orient-preflight/1`) that records every git command it ran, the remote, the fetch result
and times, the default branch and how it was discovered, the fetched and checked-out SHAs and
trees, the working-tree status with declared paths separated from unrelated changes, the
ahead/behind counts and commit lists, the classification, the action taken, and the examined
checkout. It is standard-library Python with no result authority (SD10). The gate
(`scripts/check.sh`) does not run it: the check needs the network; the gate must not.

```
python -I -X utf8 scripts/orient_preflight.py orient  [--repo DIR] [--remote origin]
    [--expect-url URL] [--sync] [--allow-dirty PATH ...] [--worktree DIR] [--receipt FILE]
python -I -X utf8 scripts/orient_preflight.py recheck --baseline SHA [--repo DIR] [--receipt FILE]
```

| Exit | Meaning | What the session does |
|---|---|---|
| 0 | snapshot established: the examined checkout (HEAD, or the new worktree) is the fetched tip, with no changes beyond the declared paths | continue with step 6 from the examined checkout |
| 2 | fetch failed: no current snapshot | stop; record; do not reconstruct or execute NEXT |
| 3 | snapshot identified, checkout not current (behind without `--sync`, ahead, diverged, unrelated dirty work, or a refused fast-forward); nothing was changed | rerun with `--sync` only on a clean, behind-only checkout of the default branch; otherwise rerun with `--worktree DIR` |
| 4 | `recheck`: the target moved since the baseline | stop; re-orient on the new tip; integrate deliberately |
| 1 | usage error, identity mismatch, or an unexpected git failure | stop; the receipt carries the error |

The preflight never force-pushes, resets, checks out over changes, deletes, or merges anything
but a fast-forward; `--worktree` only adds a detached worktree at the fetched tip. A receipt is
written with `x` mode and is never overwritten.

### D3 — Examination accounting

- SD15's disclosure (step 0) precedes the preflight. The disclosure makes exactly one change in
  the working tree, the append to `PROGRAM/HANDOFF.md`; the examination runs the preflight with
  `--allow-dirty PROGRAM/HANDOFF.md`, and the receipt lists that path under `allowed_present`
  and nothing under `unrelated`. Any other change is unrelated work and sends the examination to
  a worktree.
- The disclosure is never erased, reverted or rewritten to obtain a superficially clean tree. If
  the examined checkout turns out to be behind and the fast-forward is refused because the
  incoming commits also touch `PROGRAM/HANDOFF.md`, the examination continues in a worktree at the
  fetched tip and carries its disclosure forward: the same text, appended there as the first
  action in that checkout, marked as carried from the original checkout, whose own append is left
  as it stands. The time of the original disclosure is the disclosure time.
- The preflight establishes a snapshot; it does not establish eligibility. Whether a session is
  cold is decided by SD15 and ADR-0005 (launch context, memory content, disclosure order), and
  Gate S1 passes only on the examination's own §2 result. Session 22 remains ineligible and is
  recorded as an unsuccessful attempt; no later synchronization turns it into a valid
  examination.
- **Preparing a synchronized clean workspace can occur outside the examination.** An informed
  session may fetch, fast-forward a clean checkout of the default branch, and leave it clean (as
  Session 22 did and as this session does) so that a later fresh executor finds the checkout at
  the remote's tip. That preparation is not part of the examination: the fresh executor still
  performs its own SD15 disclosure first and its own preflight with its own receipt, and its
  record states the fetched SHA it verified.

### D4 — Verification of the failure mode

`scripts/orient_preflight_cases.py` builds a bare remote and clones under a new directory and
drives the preflight through the meaningful cases, recording every command and outcome in
`cases.json`: (1) after another clone pushes, a stale clone's `git status -sb` shows no behind
count and its cached `origin/main` equals its `HEAD` while the remote tip differs; (2–3) the
preflight's fetch exposes the newer snapshot, lists the remote-only commit, and exits 3 with
`HEAD` unchanged — the stale checkout is not treated as current; (4) a clean, behind-only
checkout synchronizes by fast-forward only and ends at the fetched tip; (5) with a local commit,
an uncommitted edit and an untracked file, `--sync` exits 3 and changes nothing, and `--worktree`
yields an isolated checkout at the fetched tip while the original keeps its commit and its dirty
work; (6) with the remote unreachable, the preflight exits 2, records no snapshot and leaves
`HEAD` unchanged; (7) after the remote moves again, `recheck --baseline` exits 4 with the new tip
and the new commits, nothing having been published, and exits 0 against the current tip; (8) an
examination's HANDOFF append counts as an unrelated change without an allowance (exit 3) and as
the expected change with `--allow-dirty` (exit 0), and the appended text survives. The run of
2026-10-21 passed every case (`analysis/s1-orientation-repair/evidence/orient-preflight-cases.json`).
An offline fixture proves what the preflight does; it establishes nothing about the live remote's
current state. The live receipts of the same session
(`analysis/s1-orientation-repair/evidence/live-orient-*.json`) record the real checkout at the
fetched `origin/main` `d8c0d9cbcef0af5249cbf439808b74d8828bd69d`.
